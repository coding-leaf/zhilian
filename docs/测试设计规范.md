## 1 总则

> 测试代码与产品代码**同等重要**，违反以下规范等同违反产品质量标准。

### 1.1 三大原则

| 原则 | 含义 |
| --- | --- |
| **只锁正确行为** | 测试只断言**期望**行为，绝不锁住当前 bug |
| **mock 跟随接口** | `MagicMock(spec=Class)` 优先，自定义 stub 受限 |
| **契约优先于实现** | 断言**返回值/异常契约**，不依赖**内部状态/私有字段** |

### 1.2 三大反模式

| 反模式 | 替代 |
| --- | --- |
| `except Exception` 测试断言 | `pytest.raises(SpecificException)` |
| `_closed` 等私有字段断言 | `m.close.assert_not_called()` |
| `class _StubSession(Session): __init__: skip` | `MagicMock(spec=Session)` |

## 2 测试设计流程（强制 4 步）

> 编写任何单测前，必须先**完成**以下 4 步设计文档。

### 2.1 等价类划分

| 输入维度 | 等价类清单 |
| --- | --- |
| 状态 | TIMEOUT / NOT_STARTED / IN_PROGRESS / PARTIALLY_GRADED / PAUSED / SUBMITTED / COMPLETED |
| 用户权限 | 同用户 / 其他用户 / 越权（无 session） |
| 数据存在性 | 存在 / 不存在 / 已删除 / 已归档 |

### 2.2 边界值清单

| 边界维度 | 边界值 |
| --- | --- |
| 数值 | 空集合、None、极小（0/1）、极大（2^31-1） |
| 字符串 | 空串、特殊字符、超长（>1K） |
| 时间 | None、过去、跨边 |

### 2.3 错误推测

| 错误维度 | 错误场景 |
| --- | --- |
| 异常 | QueueError / SQLAlchemyError / ValueError |
| 资源耗尽 | 内存满、连接超时 |
| 并发 | 双发同一 key、竞态条件 |

### 2.4 路径覆盖

| 路径维度 | 路径清单 |
| --- | --- |
| 正常路径 | 全部条件为真 |
| 错误路径 | 每个 raise 分支 |
| 边界路径 | 边界值的两个方向 |

## 3 Mock/Stub 规范

### 3.1 `MagicMock(spec=Class)` 优先

```python
# ✅ 正确：spec 跟随 SQLAlchemy 接口
injected_session = MagicMock(spec=Session)
injected_session.close.assert_not_called()

# ❌ 错误：自定义 stub 跳过 __init__
class _StubSession(Session):
    def __init__(self):
        self._closed = False  # 与真实 Session 状态机脱节
```

### 3.2 自定义 stub 受限场景

| 场景 | 是否允许 | 条件 |
| --- | :---: | --- |
| `MagicMock(spec=Class)` 可满足 | ✅ 推荐 | — |
| 需要复杂行为（多方法交互） | ⚠️ 谨慎 | 必须有 docstring + 评审通过 |
| 跳父类构建类型覆盖 | ❌ 禁止 | — |
| `iter([...])` 隐式 StopIteration | ❌ 禁止 | 用 `itertools.cycle` 替代 |

### 3.3 断言方式

| 断言对象 | 推荐 | 反模式 |
| --- | --- | --- |
| 方法调用次数 | `m.close.assert_called_once()` | — |
| 方法调用参数 | `m.enqueue.assert_called_once_with(task_name="...")` | — |
| 私有字段 | ❌ 禁止 | `assert m._closed is False` |

## 4 异常处理规范

### 4.1 捕获具体异常

```python
# ✅ 正确：捕获具体异常
except (QueueError, SQLAlchemyError) as exc:
    self.session.rollback()
    raise PracticeStatusError(...) from exc

# ❌ 错误：宽捕获
except Exception:
    self.session.rollback()
    raise
```

### 4.2 评审红线

> **任何 `except Exception` 必须有显式注释说明捕获范围，且 CI 增 ruff 规则禁止**。

```python
# 例外（顶层错误处理）：仅在最外层使用，且必须注释
except Exception:  # noqa: BLE001 - 顶层兜底，防止未捕获异常导致进程崩溃
    logger.exception("unhandled error")
    raise InternalServerError(...)
```

### 4.3 测试断言

```python
# ✅ 正确：断言具体异常
with pytest.raises(QueueError) as exc_info:
    queue.enqueue(...)
assert exc_info.value.error_code == 30015

# ❌ 错误：宽匹配
with pytest.raises(Exception):
    ...
```

## 5 测试命名规范

### 5.1 方法名模板

```
test_<method>_<scenario>_<expected_result>
```

| 示例 | 说明 |
| --- | --- |
| `test_submit_practice_without_dto_raises_value_error` | 主路径参数校验 |
| `test_retry_grading_rejects_timeout_status` | 状态机拦截 |
| `test_idempotency_lock_raises_conflict_on_duplicate_key` | 强幂等并发 |
| `test_get_user_service_does_not_close_injected_session` | 资源管理 |

### 5.2 命名红线

| 规则 | 反例 | 正例 |
| --- | --- | --- |
| 行为期望必须显式 | `test_retry_grading` | `test_retry_grading_rejects_timeout_status` |
| 避免「it_works」类命名 | `test_it_works` | `test_returns_expected_user_list` |
| 避免「happy_path」 | `test_happy_path` | `test_creates_user_on_valid_input` |

## 6 测试结构规范

### 6.1 一个 test_ 方法只测一个行为

```python
# ✅ 正确：一个方法一个行为
def test_retry_grading_rejects_timeout_status(self) -> None:
    """TIMEOUT 状态必须抛 PracticeStatusError。"""
    ...
    assert exc_info.value.error_code == 40011

# ❌ 错误：一个方法多个行为
def test_retry_grading_everything(self) -> None:
    # 测试了 5 个状态 × 3 个异常 × 4 个边界
    ...
```

### 6.2 parametrize 表达等价类

```python
# ✅ 正确：参数化表达等价类
@pytest.mark.parametrize(
    ("status_value", "completed_at"),
    [
        (PracticeStatus.TIMEOUT.value, None),
        (PracticeStatus.NOT_STARTED.value, None),
        ...  # 6 项
    ],
)
def test_retry_grading_rejects_non_partially_graded_status(
    self, status_value: str, completed_at: Any
) -> None:
    ...
```

### 6.3 fixture 复用

```python
# ✅ 正确：抽取共用 fixture
@pytest.fixture
def practice_in_progress(session: Session) -> Practice:
    """构造一个 in_progress 状态的练习。"""
    ...

# ❌ 错误：每个测试都手工构造
def test_a(self) -> None:
    p = Practice(...)
    ...

def test_b(self) -> None:
    p = Practice(...)  # 重复
    ...
```

## 7 测试纪律

### 7.1 零网络 / 零外部依赖

| 项 | 规则 |
| --- | --- |
| 真实 LLM | ❌ 禁止 → fake adapter |
| 真实 OCR | ❌ 禁止 → fake adapter |
| 真实 Redis | ❌ 禁止 → MemoryIdempotencyAdapter |
| 真实数据库 | ⚠️ 仅 SQLite memory |
| 真实网络 | ❌ 禁止（CI `block_external_network`） |

### 7.2 不引入 `# pragma: no cover`

> 测试覆盖率提升源自真实测试代码，**禁止**通过 `# pragma: no cover` 豁免。

```python
# ❌ 禁止
def legacy_method(self) -> None:  # pragma: no cover
    ...

# ✅ 正确：补测试用例
def test_legacy_method(self) -> None:
    ...
```

### 7.3 断言锁行为

> 每个 test_ 方法**至少一处断言**，「只跑不断言」等同无效测试。

```python
# ❌ 错误：只跑不断言
def test_user_creation(self) -> None:
    user = service.create_user(...)
    # 没有 assert

# ✅ 正确
def test_user_creation_sets_active_flag(self) -> None:
    user = service.create_user(...)
    assert user.is_active is True
```
