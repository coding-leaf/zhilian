## 1. 问题与现状背景 (Problem)
在智练自主学习平台的资料导入主链中，拍照与扫描图片通过 OCR 转换为文本（FR-06、FR-07）。但受拍摄反光、手抖模糊、镜头遮挡、残缺折页等现实因素影响，OCR 识别结果容易产生严重乱码、空白页面或截断残页。
若直接将低质 OCR 识别结果送入知识点抽取与题目生成主链，会导致大模型幻觉泛滥、知识图谱逻辑断裂以及题干答案错误，极大浪费 LLM Token 预算并降低学习体验。

需求规范（FR-08、FR-09）与概要设计说明书（第 3.3 节）明确规定：
图片资料识别完成后，系统必须执行质量门禁并生成识别质量报告，逐页核算**乱码比例**、**有效字数**与**页面完整性**三项核心指标。对于未达到门禁标准的页面标记为不合格并记录最严重的不合格原因，暂停题目生成并引导用户就地重拍，不合格资料绝对禁止进入出题流程。

当前系统已在 `ZL-104` 中定义了 `MaterialOCRPage` 数据持久化模型，但尚缺乏底层的**纯函数质量门禁算法计算核 (`verify_ocr_quality`)**。该算法核必须作为纯函数独立运行于 `backend/app/core/algorithms/ocr_quality.py`，保证零 I/O、零网络调用，并达到判定覆盖率 100%。

## 3. 期望达成效果 (Proposed Outcome)
1. 在 `backend/app/core/algorithms/ocr_quality.py` 中实现 `verify_ocr_quality` 纯函数及其辅助纯函数；
2. 严格对齐《概要设计说明书》第 3.3 节与《软件需求规格说明书》FR-08、FR-09 规范：
   - **单页乱码率阈值**：默认上限 $\le 15\%$ ($0.15$)，基于非可识别有效字符比例与词法有效性加权核算；
   - **单页有效字数下限**：默认下限 $\ge 40$ 字符，准确统计可用中文字符与英文词汇；
   - **页面完整性检查**：基于同批页面文本长度中位数，单页文本长度低于中位数的 $30\%$ 时判定为页面不完整；
   - **不合格原因仲裁优先级**：页面不完整 (page_incomplete) > 乱码比例超限 (gibberish_exceeded) > 有效字数不足 (insufficient_chars)；
   - **5 大边界条件严格闭环**：
     - a. 文本为空或全空白：乱码率按 $100\%$ ($1.00$) 计，有效字数记 $0$，判定为不合格，原因优先记为页面不完整；
     - b. 同批单页场景 ($N=1$)：不适用中位数比较，直接由有效字数下限与乱码率两项判定；
     - c. 批次较小场景 ($1 < N < 3$，即 $N=2$)：中位数退化为算术平均值代替；
     - d. 达到最大重拍次数 ($3$ 次) 且仍不合格时的熔断提示标记；
     - e. 输入包含非法控制字符或零宽字符时的安全清洗。
3. 单元测试用例全矩阵覆盖，判定覆盖率达到 100%，行覆盖率 $\ge 95\%$，分支覆盖率 $\ge 90\%$，复杂度 $V(G) \le 10$。

## 6. 未决疑问与待探讨点 (Open Questions)
- 1. **乱码率计算口径的纯函数实现方式**：
  - 概要设计说明书第 3.3 节明确指出：乱码率是不可构成有效词的字符占比，实现上用连续字符与词典匹配的失败比例近似。
  - 由于算法核必须为纯函数且禁止依赖大型重型 NLP 外部库或外部文件 I/O，采用内置标准字符集判定（标准汉字 CJK 范围 `\u4e00-\u9fff`、全角标点、ASCII 英文单词与标准标点）加异常字符/乱序杂乱符号比率的规则实现，既高效轻量（毫秒级执行），又具备完全确定性。
