# 1 引言

本章说明这份设计文档要解决的问题、它约束哪些人，以及它依据什么内容编制。概要设计要补上需求文档有意留下的空白：模块怎么切、数据怎么流、接口怎么定、算法在什么条件下返回什么结果、哪些部分可以脱离外部服务被单独验证。这些内容在需求阶段回答不了，在详细设计阶段回答又太晚，因为模块边界一旦写进代码就难以改动。

## 1.1 编写目的

本文档给出智练自主学习平台 V1.0 的概要设计，作为本期编码、单元测试设计与部署实施的共同依据。文档写完之后，开发人员应当知道每个模块的职责范围、对外暴露的接口形态以及模块之间允许的依赖方向；测试人员应当知道哪些逻辑属于可脱离数据库与网络运行的纯函数、这些函数的输入输出是什么、边界样本怎么构造；负责部署的成员应当知道容器如何编排、配置与密钥从何处读取、失败后如何回滚。
本文档不定义产品功能，功能需求的唯一来源是软件需求规格说明书 V2.0，两者不一致时以需求文档为准。本文档不写字段级数据字典与穷举式接口字段表。本文档不覆盖本期明确排除的范围，包括院校教务对接、班级管理、在线授课、支付结算、公开社区与内容审核后台。设计内容与需求条目之间保持可追溯：第 2.4 节的模块划分表为每个模块标注对应的功能需求编号，第 7.1 节的纯函数清单为每个算法模块标注覆盖的非功能需求，本文档中的阈值参数默认值同时注明取值依据。

## 1.2 读者对象

开发人员是本文档的主要读者。第 2 章的模块边界与依赖方向、第 5 章的接口约定属于编码前必须确认的内容；第 6 章的算法处理规则与边界处理属于实现时必须逐条对照的内容。本文档不使用"处理得当""结果准确"这类无法判定的表述，凡涉及判定行为的位置都给出具体数值或明确的条件组合。测试人员需要重点阅读第 6 章与第 7 章，前者给出的输入、输出、处理规则、边界处理与异常情况可以直接转成等价类划分与边界值取值的依据，后者给出的纯函数清单、外部依赖替换方式与测试分层目标是测试计划编写的起点。负责部署的成员需要阅读第 3.1 节的部署拓扑、第 8 章的安全设计与第 9 章的部署运维设计，这三处规定了容器数量、端口与数据卷、配置项来源、备份与回滚步骤。

# 2 总体设计

本章回答系统整体分成哪几层、为什么这样分，以及每一层负责什么、不负责什么。分层的目的不是画一张架构图，而是让"哪些代码可以在没有网络和数据库的机器上跑起来"这个问题的答案落在目录结构上。本章的三个设计原则、一个编排层定位与一张模块划分表构成后续八章的约束条件。

## 2.1 设计目标与原则

设计目标按优先级排列，前一条不被后一条牺牲。第一条是可测性，需求 NFR-22 要求资料分块、判题阈值判定、掌握度计算、知识点质检与题目质检五块逻辑必须脱离数据库与网络单独执行。第二条是结论可信，判题与掌握度的计算结果必须可重复、可解释，同一份输入在任何时间、任何机器上得到同一个结果。第三条是外部依赖可退让，OCR 与大语言模型都属于不可完全信任的外部能力，任一服务不可用时主链要么降级继续，要么停在可恢复的状态，不允许产生静默的错误结论。第四条是成本可控，单份资料从导入到完成一次练习的大模型调用次数有明确上限，超出后任务停止，对应 NFR-29。
第一条设计原则是纯函数在核心、语言模型在边缘。分值合成、阈值判定、档次映射、质检判断、掌握度聚合这五类计算全部写成纯函数；语言模型只负责生成题目候选、判断主观答案的语义接近程度、从资料片段中抽取候选知识点。模型输出天然带随机性，把判定权交给模型会让判题结论无法用固定输入复现，测试人员也就无法为它写断言；判定权收回到纯函数之后，模型只提供候选或语义评分，候选不合格由纯函数拦下，语义评分落到阈值区间时由纯函数决定下一步动作。
第二条设计原则是确定性流程优先于开放式 Agent。主链是一条固定顺序的流水线，依次为资料导入、解析分块、知识点抽取与建树、题目生成与质检、练习与作答、混合判题、掌握度更新、诊断报告与继续练习。流水线每个环节的输入输出形态固定，任何一环失败都能定位到具体阶段，重试可以从失败阶段继续而不必整条链重跑，对应 NFR-07 与 NFR-12整条流水线上，模型可以行使选择权的位置只有四个：选解析器时，模型在五种格式解析器的名称列表中选择一个，返回内容不在列表内则使用扩展名回退规则；检索相关片段时，模型可以在语言化查询与关键词查询之间选择，也可以在候选片段集合中挑选进入出题上下文的部分；判题时查规则与原文，模型通过工具读取题目的评分细则与来源片段，避免凭空评判；诊断时取统计，模型通过工具读取知识点的答题统计，用于生成可能原因的表述。四个位置之外，模型不参与任何控制流决策。
第三条设计原则是检索先于生成。生成题目之前必须先检索到与目标知识点相关的知识片段，检索结果为空或相似度全部低于阈值时系统拒绝为该知识点出题，并把未生成原因返回用户，对应 FR-21，阈值与判定过程见第 4.2 节与第 6.5 节。这条约束牺牲一部分出题数量，换来的是每道题都能被用户核对。与之配套的是溯源粒度按资料类型区分：原生文档资料定位到页码或具体知识片段，图片资料本期只承诺定位到第几页照片，两类资料在界面上的溯源表述不同，对应 FR-10。

## 2.2 系统总体架构

系统分为七层，自上而下依次为客户端层、接入层、接口层、编排层、业务服务层、纯函数算法层、数据访问层，另有一组外部能力适配器与一组异步任务消费者横向支撑，整体结构见图 2-1。
图 2-1　智练系统总体架构图
客户端层是微信小程序，采用 uni-app 配合 Vue 3、Vite 与 TypeScript 开发，界面控件使用 Wot Design Uni。客户端只承担展示与交互，不承担判定逻辑；作答进度遵循本地先行、后台同步的策略，同步失败不阻断用户继续作答，对应 FR-34接入层由 Nginx 承担，负责 HTTPS 流量终结、请求体大小限制与按路径前缀转发，微信小程序要求服务端域名完成备案并配置有效证书，接入层不做业务判断，也不承担鉴权。
接口层是 FastAPI 应用，采用 Uvicorn 多进程方式运行，只做解析请求、用 Pydantic v2 模型校验入参、把服务层返回值转换为响应模型三件事。接口层不出现数据库会话操作，不直接调用外部能力，也不包含超过一行的业务判断。
编排层由 LangGraph 与 LangChain 构成，负责六条工作流的状态建模、条件路由、检查点持久化与失败续跑，定位与边界见第 2.3 节。业务服务层承担事务边界与多步骤编排，是唯一允许开启数据库事务的层；资料导入、知识点、出题、练习、判题、诊断六个服务各自负责本环节的编排与副作用处理，不实现算法细节。纯函数算法层是系统的判定核心，包含资料分块、知识点质检、题目质检、判题阈值与匹配、掌握度计算五块，另含答案规范化、相似度合成、档次映射等无副作用辅助函数；算法层只依赖标准库与 Pydantic 数据模型，不允许导入 Web 框架、数据库驱动、HTTP 客户端、缓存客户端与对象存储客户端，也不允许导入服务层与数据访问层的模块。
数据访问层封装针对数据表的查询与写入以及向量检索。所有涉及用户数据的查询必须带上用户条件，用户条件由服务层从登录态取得后传入，不接受客户端参数作为归属依据，对应 FR-60 与 NFR-14；向量检索在本层封装为带阈值与条数上限的函数。外部能力适配器用协议接口描述 OCR、大语言模型、向量化、对象存储四类能力，具体实现按供应商替换，业务代码不引用供应商 SDK 的客户端类型与异常类型，对应 NFR-26。异步任务消费者是独立进程，从 Redis 队列取任务并驱动编排层执行。

## 2.3 技术选型与理由

技术选型在决策基线给定的范围内展开，本节补充选择理由以及被放弃的替代方案，汇总见表 2-1。
表 2-1　技术选型与选择理由
| 层次 | 选型 | 选择理由与放弃的替代方案 |
| --- | --- | --- |
| 小程序端 | uni-app（Vue 3 + Vite + TypeScript）+ Wot Design Uni | 一套代码可编译到微信小程序，对微信原生接口有成熟封装；Wot Design Uni 提供表单、列表、弹层控件与 Markdown 渲染能力。原生小程序开发少一层编译，但组件生态与类型支持较弱，类型错误只能运行期暴露 |
| 服务端 | Python 3.11+ / FastAPI，Pydantic v2 | 异步 I/O 模型适配外部服务调用占比高的负载；Pydantic v2 用类型定义同时完成运行时校验与 OpenAPI 生成。Flask 与 Django 在异步编排和类型校验上需要额外拼装，接口契约需手工维护 |
| 编排层 | LangGraph + LangChain | 状态图把六条工作流表达为节点与边，条件分支显式写在路由函数中而不是埋在提示词里，检查点机制支持断点续跑。纯代码编排调试直观，但多分支与断点续跑要重复造轮子；通用工作流引擎对 Python 算法函数调用不自然 |
| 业务算法 | 独立纯函数计算核 | 需求 NFR-22 要求核心算法脱离数据库与网络可测，纯函数形态最直接地满足该要求。写进服务层可以让调用链更短，但边界用例需要构造数据库与网络桩 |
| 关系与向量存储 | PostgreSQL 16 + pgvector | 关系数据与向量数据同库，资料删除时片段、向量与知识点可在一个事务内处理；本期向量规模按单用户不超过 3000 个片段估算。独立向量库检索更快，但引入跨库删除与备份的一致性问题 |
| 任务队列与缓存 | Redis 7 | 承担解析、识别、出题、AI 判题的异步任务队列与访问令牌缓存，单实例足以支撑本期并发目标。数据库轮询队列实现简单，但空转开销与延迟不理想，且难以表达可见性超时 |
| 对象存储 | MinIO | S3 兼容接口；数据库只保存引用与摘要。直接把文件存数据库会让备份体积与恢复时间随资料量线性增长 |
| 接入层 | Nginx | 终结 HTTPS、限制请求体大小、统一转发接口，微信小程序对域名与证书的要求在这里落实。由应用直接监听 443 会让证书续期与应用发布耦合 |
| 部署 | Docker Compose | 六个服务加四个消费者进程的规模下编排复杂度低，单机部署即可满足 NFR-06 的并发目标，本地与测试环境共用同一份编排文件。容器编排平台在多节点调度上更强，但需要额外维护集群与网络方案 |
| OCR | 腾讯云通用印刷体识别 | 对印刷体中文识别质量稳定，支持多页批量提交与版面分析。本地识别方案不需外部费用，但安装体积与拍照件的识别质量不可控 |
| 大语言模型 | DeepSeek 或通义千问，经能力网关统一调用 | 两家供应商接口形态接近，通过网关抽象后可按任务类型或成本切换，供应商可配置，满足 NFR-26 与 NFR-28。绑定单一供应商可以省去适配代码，但供应商限流或调价时没有退路 |

编排层的定位需要单独说明，因为它最容易被误解为"系统的大脑"。LangGraph 在本项目中承担四项职责：状态建模，六条工作流各自定义一份状态结构，状态中只放跨节点传递的数据，例如任务标识、资料标识、片段标识列表、候选知识点列表与判题中间结果，不放业务结论；条件路由，把质检结论、匹配度区间、AI 判题超时这类判断显式写成边上的条件函数，条件函数的输入是状态对象，输出是下一个节点名；检查点持久化，每个节点执行完成后把状态写入持久化存储，进程重启后可从最近一次检查点继续，对应 NFR-12；失败续跑，可重试异常回到同一节点重试，不可重试异常把任务置为失败并记录失败阶段，用户重试时从该阶段继续，对应 FR-05 与 NFR-07。
LangGraph 在本项目中不承担四项职责。它不计算任何分值，判题得分、掌握度数值、质检得分全部由算法层的纯函数给出。它不判断质量门禁的通过与否，质检结论由算法函数返回，编排层只按结论选择走重抽分支还是继续分支。它不读写业务数据表，编排层的检查点存储与业务库分离。它不直接调用供应商 SDK，模型调用一律经能力网关，超时、重试与响应结构校验都在网关内部处理。

# 3 运行设计

本章描述系统在运行时的形态与关键流程的执行顺序，回答两个问题：进程部署在哪里、以什么顺序协作；一次用户操作在系统内部经过哪些参与方、每一步的输入输出与失败分支是什么。五个流程覆盖主链的全部环节，其中包含三处门禁分支与一处降级路径，这三处分支是本期实现与测试的重点。

## 3.1 部署拓扑

本期采用单机 Docker Compose 编排，物理上部署两台机器：一台 4 核 8 GB 的应用机承载全部容器，一台轻量机器承载数据库的定时备份与日志归档。按 NFR-06 的并发目标，100 个并发用户中 10 个同时提交任务，应用进程的 CPU 占用主要来自文档解析与向量序列化，4 核足以覆盖。
编排包含十个运行单元，拓扑见图 3-1。nginx 容器对外暴露 443 端口，把 /api/v1 前缀的请求转发到 backend 服务。backend 服务以 Uvicorn 启动 4 个进程，并发上限按每个进程 100 个连接配置。worker-parse、worker-ocr、worker-generate、worker-grade 四个消费者进程从 Redis 的不同队列取任务，其中 worker-ocr 出网访问腾讯云 OCR，worker-generate 与 worker-grade 出网访问大模型能力网关；四个进程共用同一份后端镜像，通过启动参数区分消费队列。postgres 容器挂载持久化数据卷并加载 pgvector 扩展，max_connections 设为 200。redis 队列与缓存使用不同的库编号，minio 挂载数据卷保存资料原件、页面照片与解析中间产物。只有 nginx 暴露宿主机端口。
图 3-1　Docker Compose 部署拓扑图
环境划分三套。开发环境在成员本机以 compose 的开发编排文件启动，只保证数据库、缓存与对象存储三个容器，后端以热重载模式运行，外部能力使用本地桩实现。测试环境使用单机 compose 全部服务，外部能力使用测试额度的真实接口，数据库允许随时清空重建。生产环境与测试环境的差异只有密钥来源、日志级别与数据卷的备份策略三项。
队列参数按如下取值。解析队列与识别队列各 2 个并发，出题队列 2 个并发，判题队列 4 个并发，全机异步任务总并发不超过 8。任务在队列中的可见性超时设为 600 秒，超时未确认的任务重新入队，重试上限为 3 次，退避间隔依次为 30 秒、120 秒、600 秒，超过上限后任务置为失败并记录失败阶段。接口层普通请求超时 15 秒，上传与出题请求超时 60 秒。

## 3.2 关键流程时序

本节用编号步骤描述五个关键流程，每步标注参与方。五个流程共用两条约定：耗时操作以异步任务方式执行，客户端通过状态接口轮询，轮询间隔 2 秒，单次请求超时 30 秒；可能重复提交的写操作携带幂等键，幂等键由客户端在动作触发时生成，服务端以幂等键加接口路径为唯一约束。

### 3.2.1 资料导入与解析流程

这个流程覆盖从用户选择文件到资料进入可出题状态的完整过程，包含接收校验、解析器调度、识别质量门禁与分块四个阶段，时序见图 3-2。
图 3-2　资料导入与解析时序图
1. 小程序端调用微信的聊天记录选文件接口或相册接口取得临时文件路径，向对象存储申请上传凭证，随后把文件直接上传到 MinIO，携带服务端下发的资料标识与幂等键，上传成功后调用资料落库接口。
1. 后端接口层校验文件大小是否落在 1 KB 至 50 MB 区间、扩展名是否在允许列表内，并用文件头字节与扩展名交叉比对，对应 FR-02 与 FR-03；校验通过时服务层创建资料记录，状态为排队中，写入解析任务并向解析队列投递，校验不通过时接口直接返回错误码 10001 或 40001 并写明实际大小、实际类型或加密状态。
1. 后端返回资料标识与任务标识，小程序端每 2 秒轮询一次状态查询接口。
1. worker-parse 取出任务，通过一次工具调用让模型在五种格式解析器的名称列表中选择解析器；模型超时或返回名称不在列表内时按扩展名回退，回退记录写入任务日志。
1. 解析器输出文本与来源信息：原生文档记录页码与章节标题，演示文稿记录幻灯片序号，文本文件记录段落序号，对应 FR-06；服务层随后按 800 字上限与 120 字重叠执行分块，规则见第 6.1 节。
1. 图片资料进入识别分支：worker-ocr 调用腾讯云通用印刷体识别，单张图片超时 20 秒，超时按可重试异常处理，识别结果按页面保存；服务层对每页识别文本计算质量指标并执行门禁判定，规则见第 6.2 节。
1. 全部页面通过门禁时跳到第 9 步；存在不合格页面时流程暂停，资料状态置为失败并标记需要重拍，对应 FR-09。小程序端展示不合格页面列表与逐页原因，用户重拍后通过同一条上传路径替换该页图片，复用原资料标识；worker-ocr 只对替换的页面重新识别。重新判定后仍不合格且该页已重拍三次时，提示用户改用其它导入方式或删除该页，资料不进入出题流程。
1. 全部页面通过后，服务层把识别文本与原生文档文本合并为同一份解析结果，来源信息保留资料类型标记。
1. 服务层把知识片段批量写入数据库，同时把片段文本提交向量化，向量与片段在同一事务内建立关联；资料状态置为已完成，任务终态与各阶段耗时写入任务记录，状态接口返回完成状态与片段数量。
失败分支有三类。上传中断时幂等键保持不变，重试上传不会产生第二条资料记录。解析器抛出的格式异常归类为不可重试异常，任务直接失败并记录失败阶段。识别接口返回限流错误时按可重试异常处理，退避间隔依次为 30 秒、120 秒、600 秒。

### 3.2.2 知识点抽取与建树流程

这个流程把知识片段加工为带层级关系的知识点集合，中间穿过一次后台质检门禁，门禁不通过时触发有限次数的重抽，时序见图 3-3。
图 3-3　知识点抽取与建树时序图
1. 资料状态置为已完成时，服务层向生成队列投递知识点抽取任务，任务携带资料标识与解析批次号。
1. worker-generate 取出任务，按章节顺序把片段集合切分为每批不超过 40 个片段的抽取单元，单份资料最多 12 批，超出部分不再抽取并标注截断数量。
1. 编排层对每一批调用一次模型，要求返回知识点的名称、简述与来源片段标识，返回结构由 Pydantic 模型校验；返回结构不合法时重试一次，第二次仍不合法时该批标记为抽取失败。
1. 服务层对全部批次结果做去重与合并，名称规范化后相同或相似度高于 0.92 的知识点合并为一个，随后用一次模型调用建立层级关系，输入是去重后的名称列表与来源章节信息，输出是父子关系列表，层级深度上限为 5。
1. 服务层计算质检所需统计量：知识点总数、层级深度的最大值与分布、每个知识点名称的长度与字符构成、每个章节的片段占比与对应的知识点数量。
1. 知识点质检模块以知识点集合与统计量作为输入，逐项执行四项检查，判定规则与阈值见第 6.3 节。
1. 质检通过时服务层保存知识点与层级关系，把知识点与来源片段的关联一并写入，资料的知识结构可信度标记为高，流程结束；质检不通过时把不通过原因拼接为提示词补充段落，重新投递抽取任务，重抽计数加一，对应 FR-17。
1. 重抽两次仍不通过时，服务层采用本次抽取结果保存，把知识结构可信度标记为低，并在诊断报告生成时携带该标记，对应 FR-18 与 FR-53。每次重抽的提示词追加前一次的不通过原因，例如"知识点数量为 268 个，超出同规模资料的区间上限"。

### 3.2.3 题目生成与质检流程

这个流程从用户配置出题参数开始，到题目进入可用集合或待处理区结束，其中检索环节是硬性前置条件，时序见图 3-4。
图 3-4　题目生成与质检时序图
1. 小程序端提交出题配置，包含资料标识、知识点标识列表、题数、题型集合与难度筛选，题数范围为 1 至 50，对应 FR-27；接口层校验取值边界与知识点归属，归属校验以服务端登录态中的用户标识为准，配置中出现他人知识点直接返回错误码 20002。
1. 服务层为每个目标知识点执行检索，采用向量相似度与关键词匹配混合的方式，先取余弦相似度最高的 20 个片段，再按关键词命中数重排，取前 4 个片段作为出题上下文，片段总长度上限 2400 字。
1. 检索结果为空或全部片段相似度低于 0.35 时，系统拒绝为该知识点出题，把未生成原因记为缺少可溯源片段并返回用户，对应 FR-21。
1. 编排层把知识点名称、简述、出题上下文与题型要求组装为生成请求，调用能力网关，单次生成请求超时 60 秒。
1. 模型返回候选题集合，每道题包含题干、选项、答案、解析、难度与来源片段标识，主观题的返回结构额外包含评分细则，细则要点总分与题目分值一致，对应 FR-23；服务层校验每道题的六个必填项，缺失任一项的题目直接进入待处理区而不进入质检队列，对应 FR-22。
1. 服务层为每道题的题干与选项组合计算向量，与同一资料下已通过质检的题目向量做相似度比较，相似度高于 0.90 的判为重复题；题目质检模块随后执行四类检查，规则见第 6.4 节，输出保留题目集与逐题剔除原因。通过质检的题目写入题目表，状态为可用；被剔除的题目写入待处理区并保存剔除原因，对应 FR-24 与 FR-25。
1. 服务层把生成结果返回小程序端，包含题目列表、每题的来源片段、未生成的知识点及原因、待处理题目数量。用户对单道题执行修改、删除或重新生成；修改后的题目重新执行来源检查与歧义检查，答案冲突与重复检查按修改后的内容重跑，对应 FR-26。
能力网关返回可重试错误时按退避策略重试一次，第二次仍失败时该批任务标记为失败，已生成并通过质检的批次保留可用，用户可以对失败批次单独重试。生成调用按资料维度累计，单份资料从导入到完成一次练习的调用次数上限为 120 次，超出后任务停止并提示用户稍后重试，对应 NFR-29。

### 3.2.4 练习提交与混合判题流程

这个流程从用户逐题作答开始，到逐题反馈与错题记录生成结束，其中包含离线判题与 AI 判题之间的切换判定以及 AI 判题失败时的降级路径，时序见图 3-5。
图 3-5　练习提交与混合判题时序图
1. 小程序端在用户每次作答后调用保存接口，请求携带练习标识、题目标识、答案内容与作答时间戳，接口以练习标识加题目标识作为幂等键；服务层写入作答记录并返回已答题数，客户端在网络不可用时把答案留在本地队列，恢复网络后按时间顺序补发，对应 FR-34。
1. 用户点击交卷时小程序端调用提交接口，请求携带练习标识与客户端生成的提交幂等键；服务层做唯一约束检查，已存在同键的判题任务时直接返回该任务标识与任务状态，对应 FR-35。
1. 服务层校验答卷完整性，统计未作答题目数量并在响应中返回，客户端据此提示用户确认或返回补充作答，对应 FR-36；随后创建答卷记录与判题任务，把答卷状态置为判题中，向判题队列投递任务，交卷接口在此返回。
1. worker-grade 取出任务，逐题读取题目类型与作答记录，按题型分流。客观题由离线判分函数处理，选择题比对选项标识集合，多选题要求正确选项集合完全一致，判断题比对二值结果，填空题在比对前先做答案规范化，规范化覆盖首尾空白去除、全角半角统一、大小写统一与数字格式归一，对应 FR-37 与 FR-38。
1. 主观题先执行离线匹配，匹配函数以评分细则要点、关键词表、否定词表与用户答案为输入，输出匹配度与命中要点列表，对应 FR-39，计算规则见第 6.5 节。
1. 判题阈值模块对匹配度执行区间判定：匹配度不低于 0.82 时按离线判对处理，低于 0.45 时按离线判错处理并进入转 AI 判定，落在 0.45 至 0.82 之间同样进入转 AI 判定；离线判为错误的题目另行检查是否存在多个等价表达、要点覆盖率为零但语义相似度高于 0.55 这两类条件，四类条件满足任一即转 AI 判题，对应 FR-40。
1. 转 AI 判题的题目进入 AI 判题队列，worker-grade 通过能力网关发起调用，请求内容包含题目、参考答案、评分细则与来源片段，超时时间设为 20 秒，单题最多调用两次；返回的建议分数、命中要点、遗漏要点、原因与置信度五项内容由 Pydantic 模型校验，对应 FR-41。
1. 调用超时、返回结构不合法或网关返回不可重试错误时，该题标记为待重新判题，答案保留，不写入错误结论，对应 FR-42；用户可以在结果页面触发重新判题，选择为待重新判题或用户自评时该题的掌握度权重按最低档处理。
1. 判题完成后服务层汇总答卷得分、逐题反馈与判题来源标记，答卷状态置为已完成，对应 FR-43 与 FR-44；同时调用掌握度与诊断模块更新知识点掌握度，并把客观题错答、主观题判错或部分正确的题目写入错题记录，待重新判题的题目不写入，对应 FR-54。
1. 小程序端在状态轮询中取到完成状态后展示结果与反馈。
AI 判题的降级路径需要单独强调。关闭大模型服务后提交主观题答卷，该题必须停在待重新判题状态，答案完整保留，用户可以触发重新判题或自评，任何情况下不得在缺少有效判题结果时把题目判为错误。一次误判会把已经掌握的知识点列为薄弱项，让用户复习已经会的内容；停在待判题状态是可恢复的，代价只是结果页多一个标记。

### 3.2.5 掌握度更新与诊断报告流程

这个流程在判题完成之后触发，把答题记录加工为掌握度数值与诊断结论，并在报告末尾提供继续练习入口，时序见图 3-6。
图 3-6　掌握度更新与诊断报告生成时序图
1. 判题任务完成后，服务层在同一个事务内触发掌握度更新任务，任务携带练习标识与涉及的知识点标识列表；诊断服务读取每个知识点下该用户最近 200 条有效答题记录，记录字段包含对错、作答时间、题型与判题来源。
1. 掌握度计算函数以答题记录序列、当前时间与权重配置为输入，计算 0 至 1 的数值与四档档次，规则与边界处理见第 6.6 节；函数不访问数据库，当前时间由调用方作为显式入参传入。
1. 服务层写入掌握度记录与档次，同时保存本次练习的掌握度快照。
1. 诊断服务生成诊断报告。主要薄弱知识点取本次练习涉及知识点中掌握度最低的 3 项，每项必须关联至少一条本次练习中的答错记录，不足 3 项时按实际数量给出。
1. 退步知识点通过本次快照与上一次练习快照逐项比较得出，本次练习新增的知识点不计入退步统计，两个快照的差值小于 0.05 时不判为退步；可能原因由诊断规则函数合成，输入是题型分布、未作答数量与判题来源统计三类信息，规则见第 6.7 节，对应 FR-51。
1. 诊断服务检查知识结构可信度标记，标记为低时在报告首部增加可信度说明，对应 FR-53；随后服务层把报告、薄弱知识点清单与继续练习入口的描述一并写入诊断记录，把报告与掌握度变化返回小程序端，报告在练习结果位置展示，不新增独立页面。
1. 用户点击继续练习入口时，小程序端调用继续练习接口，请求携带原练习标识与一个幂等键；服务层先查询该用户是否存在来源为同一份诊断报告且尚未开始的薄弱知识点练习，存在时直接返回该练习标识，对应 FR-58。
1. 不存在时服务层按薄弱知识点清单检索片段并创建新练习，练习的来源标记为薄弱知识点练习，题目顺序遵循同一知识点不相邻的约束，对应 FR-30 与 FR-31；随后返回练习标识与覆盖知识点数量。
这个流程中的异常情况有两处。某知识点在最近 200 条记录中不存在有效答题记录时，掌握度按未学档次返回，该知识点不进入薄弱知识点清单。判题任务存在待重新判题的题目时，这些题目不计入本次诊断的答题记录集合，报告在结论位置标注待判题数量。

# 4 数据设计

本章描述系统持久化的数据形态与存取方式，回答三个问题：系统有哪些实体、实体之间怎么关联；向量数据怎么存、怎么检索、检索结果如何参与出题；资料原件与解析中间产物放在哪里、多版本怎么处理。本章不写字段级数据字典，字段的名称、类型、长度、约束与索引由代码中的模型定义与迁移脚本承担。

## 4.1 数据模型

系统的主要实体有十五个：用户、学习资料、资料版本、识别质量记录、知识片段、知识点、知识点质检记录、题目、题目质检记录、练习、答卷、作答记录、判题结果、掌握度记录、诊断报告、错题记录。实体关系围绕三条线索组织：资料加工线索从学习资料经资料版本、知识片段、知识点到题目；练习线索从练习经答卷、作答记录、判题结果到掌握度记录与诊断报告
用户是最上层实体，其余实体全部通过用户标识建立归属。学习资料保存名称、格式、大小、导入方式、当前版本引用与状态；资料版本是独立实体，保存原文件在对象存储中的引用、内容摘要、解析状态与失败阶段。把版本拆成独立实体而不是在资料表上追加字段，因为 FR-12 要求重新导入同名或同内容文件时按新版本处理且不覆盖既有版本的知识片段与题目，既有练习记录必须仍能追溯到当时的版本。
识别质量记录挂在资料版本上，保存每页的乱码比例、有效字数、页面完整性判定、不合格原因与重拍次数，与页面序号一一对应，重拍后更新对应页的记录而不是新增一页。知识片段保存文本内容、来源信息、顺序号与向量；来源信息按资料类型区分，原生文档保存页码与章节标题，演示文稿保存幻灯片序号，文本文件保存段落序号，图片资料保存照片页序。知识点保存名称、简述、层级关系、抽取批次号与来源片段关联。知识图谱在本期以层级关系加质检记录表示，不单独建立图结构，层级关系用父子引用表示，深度上限为 5。知识点质检记录保存逐项得分、整体结论、重抽次数与每一次的不通过原因。
题目保存题型、题干、选项、答案、解析、难度、评分细则与状态，状态区分可用与待处理，与知识点、知识片段均建立关联。题目质检记录与题目在同一生成批次中保存，被剔除的题目保留剔除原因与批次号。题目的修改痕迹单独保存，记录修改前后的内容摘要与修改时间，满足 FR-26 的要求。
练习保存用户配置的知识点范围、题型构成、题数与来源标记，来源标记区分按知识点范围创建与从诊断报告创建两类。答卷属于某个练习与某个用户，保存提交时间、用时、幂等键、状态与得分；作答记录按题目粒度保存用户答案、作答时间与判题结果引用。判题结果分离线与 AI 两条记录保存，最终结果以来源标记指向离线、AI 或用户自评三者之一。掌握度记录按知识点粒度保存数值、档次、计算时间与快照序号。诊断报告保存主要薄弱知识点、退步知识点、可能原因、下一步建议、知识结构可信度标记与关联练习。错题记录按用户与题目建立唯一约束，保存错误类型、错误次数与最近错误时间。实体关系见图 4-1。
图 4-1　智练主要数据实体关系图
数据删除的影响范围按 FR-13、FR-61 与 FR-62 确定。删除单份资料时，其资料版本、知识片段、向量、知识点、知识点质检记录、题目与题目质检记录一并删除；已有答卷中的作答记录保留判题结果与题目内容快照。删除账号时全部实体按用户标识清理，采用逻辑删除加定期物理清理的方式，逻辑删除后所有访问路径立即不可达，物理清理任务每天执行一次，清理七天前的记录。向量数据的删除与关系数据在同一事务内完成。
归属约束在表结构层面有对应设计。全部业务表都带用户标识列，针对用户数据的查询统一以用户标识作为首个过滤条件；涉及子实体的查询通过连接回到所属资料或练习再校验用户标识，不采用"客户端传资料标识即认为是本人资料"的写法。这条约束与第 8.1 节的鉴权约定配合，构成数据隔离的两道防线。

## 4.2 向量存储与检索设计

向量数据存储在 PostgreSQL 的 pgvector 扩展中，向量统一为 1024 维，由能力网关的向量化能力生成。维度选 1024 的原因是该维度在中文文本语义检索上的表现与调用成本之间取平衡。向量列采用定长向量类型，避免变长向量带来的索引退化；向量维度与向量化模型绑定，更换为其它维度的模型时必须重建向量列与索引，这一约束写入第 10 章的待确认项。
索引策略分两处。知识片段的向量列建立 HNSW 索引，距离度量采用余弦距离，索引参数取 m 为 16、ef_construction 为 200，查询时的动态候选列表长度取 40。选择 HNSW 而不是 IVFFlat 的理由有三条：HNSW 不需要预先训练聚类中心，资料导入是持续发生的过程，不存在稳定的建索引时机；HNSW 在召回率与查询延迟上对参数不敏感，本期向量规模按单用户不超过 3000 个片段、全库不超过 20 万条估算；HNSW 支持增量插入，与资料分块逐批写入的形态一致。题目的题干向量列同样使用 HNSW 索引，但只用于重复题检测，检索范围强制限定在同一用户同一资料的可用题目集合内，条数上限取 10
检索与出题的配合方式有四条规定。检索先于生成，出题请求必须先经过检索步骤，检索结果为空或相似度全部低于阈值 0.35 时拒绝出题，对应 FR-21。粗排与重排分两步：粗排用向量相似度取前 20 个片段，重排用关键词命中数与片段长度做加权，取前 4 个片段进入出题上下文，加权公式为向量相似度乘以 0.7 加关键词命中率乘以 0.3，命中率的计算口径是知识点名称与简述中的实词在片段中的出现比例。上下文长度上限为 4 个片段合计 2400 字，超出时按重排得分从低到高截断，单片段保留完整段落，不从句子中间切断。出题时使用的片段标识与相似度写入题目的来源关联。
混合检索的关键词部分使用 PostgreSQL 的中文全文检索能力，配合扩展分词。选择在数据库内完成关键词匹配，因为本期需要按相似度与命中数联合排序，在数据库内可以用一条查询同时完成两步并直接返回前 4 条。向量检索有两条性能约束：检索查询必须限定用户标识与资料标识，避免全表扫描；检索请求的 95 分位延迟目标为 200 毫秒，以单用户 3000 个片段为前提测量。

## 4.3 对象存储与资料版本

对象存储保存三类对象。资料原件按用户的资料版本逐个保存，对象键由用户标识摘要、资料标识、版本号与文件扩展名组合而成，不直接把用户标识明文写进键名。页面照片作为图片资料的独立对象保存，与资料版本下的一页对应，重拍时覆盖同键对象并更新版本摘要。解析中间产物包含纯文本抽取结果与分页结构，保存为按版本组织的对象。
对象存储的访问权限全部经过服务端。小程序端上传使用短期上传凭证，由服务端按资料标识签发，有效期 15 分钟，限定对象键前缀与最大体积；下载同样使用短期凭证，有效期 5 分钟。对象存储不开放匿名读取。
资料版本的处理规则有四条。用户重新导入同名文件时，系统比对文件内容摘要，摘要相同且原版本未发生解析失败时提示用户该文件已导入并复用原版本；摘要相同但原版本解析失败时创建新版本并允许重试。同内容但元数据不同的文件创建新版本。旧版本的片段、知识点与题目保留，不随新版本导入而失效。用户在资料列表中默认看到当前版本，可以切换到历史版本查看当时的题目与练习记录。
存储容量与生命周期按四项约定管理。单用户资料原件的累计体积上限为 500 MB，达到上限时拒绝新的导入并提示用户删除历史资料。解析中间产物保留 30 天，到期后清理，清理后该版本的失败重试需要重新解析。页面照片随资料版本一并保留，不单独设过期时间。资料逻辑删除后，原文件对象在七天后的物理清理任务中删除。

# 5 接口设计

本章描述客户端与服务端之间的接口约定，回答两个问题：所有接口共用的规则是什么，以及核心接口各自承担什么职责、入参出参的关键部分是什么、异常情况下返回什么。本章不写逐字段的完整请求响应结构，完整结构由 FastAPI 依据 Pydantic v2 模型自动生成的 OpenAPI 文档提供，测试人员可以从该文档直接导出入参组合。

## 5.1 接口通用约定

接口的鉴权方式统一为登录态令牌。客户端在微信授权后调用登录接口取得访问令牌与刷新令牌，访问令牌有效期 2 小时，刷新令牌有效期 30 天并在每次刷新时轮换。除登录接口之外，全部接口都要求携带访问令牌，未携带或令牌失效时返回错误码 20001，响应体中不含任何业务字段。服务端从令牌中解析用户标识，接口入参中出现的用户标识一律忽略并记录异常，归属判定只依据令牌，对应 FR-60 与 NFR-13。
错误码采用五位数字分段，前两位标识类别，与代码管理文档第 2.5 节的登记表一致。10 段表示参数与请求格式问题，包括 10001 参数校验失败、10002 分页参数越界、10003 请求体超限。20 段表示鉴权与权限问题，包括 20001 未登录或登录态失效、20002 无权访问该资源。30 段表示外部能力问题，包括 30001 OCR 识别服务失败、30002 大模型调用超时、30003 向量化服务失败。40 段表示算法与质量门禁问题，包括 40001 资料质量不达标、40002 知识点质检未通过、40003 检索不到可溯源片段、40004 题目质检未通过。50 段表示内部与数据问题，包括 50001 数据库写入失败、50002 任务队列不可用。新增错误码必须先登记后使用。响应体固定包含错误码、面向用户的提示文案与请求标识三项，提示文案不包含内部堆栈与资料内容。
分页约定统一为页码加每页条数，参数名为 page 与 page_size，page 从 1 开始，page_size 默认 20，取值范围 1 至 100。排序默认按创建时间倒序，资料列表允许按名称与导入时间排序，题目列表允许按难度与题型排序。page 小于 1、page_size 超出范围或非整数时返回错误码 10002，不返回空列表，因为空列表会让客户端把参数错误误判为数据为空。分页响应包含总条数、当前页码与数据项三项，总条数的统计与列表查询使用同一组过滤条件。
幂等键的处理有三条规则。可能重复提交的写操作必须携带幂等键，请求头字段名为 Idempotency-Key，取值由客户端在用户动作触发时生成，长度 8 至 64 字符。服务端以幂等键加接口路径建立唯一约束，重复请求返回首次请求的结果与状态码，不产生第二条记录，对应 FR-35 与 NFR-08。幂等键的记录保留 24 小时。缺少幂等键的写请求按错误码 10001 拒绝，不采用"没有键就当作非重复请求"的宽松处理。
返回结构统一使用小写加下划线的字段命名，时间统一使用带时区的格式，耗时字段以毫秒为单位。响应中不返回资料原文全文与用户答案全文，需要展示片段内容时只返回本次请求所需的片段，长度不超过 2400 字。

## 5.2 核心接口说明

# 6 算法设计

本章是本文档的重点。系统把判定权集中在五个纯函数计算核上，这五个计算核的输入输出形态、处理规则、边界处理与异常情况在本章逐条写清。这样做有两个原因：这些算法的判定行为直接影响诊断结论的可信度，参数与分支的取值不能留给实现者临场决定；这些算法是单元测试与白盒测试的主要对象，测试人员需要据此构造等价类与边界样本。本章每个小节按输入、输出、处理规则、边界处理、异常情况组织。

## 6.1 资料分块算法

输入是解析后的段落序列、片段字符数上限、相邻片段重叠字符数、标题层级标记序列与来源信息映射，每个段落带有来源标记；输出是知识片段列表，每项包含片段文本、起止偏移、所属章节标题、来源标记、资料类型标记与顺序号。默认片段字符数上限取 800，重叠字符数取 120，重叠比例约为 15%，用于避免关键表述恰好落在片段边界处；标题层级标记缺失时片段归属到最近的上层标题。处理规则有六条。合并短段时把连续多个字符数之和不超过上限的相邻段落拼成一个片段，拼接处以换行符分隔。遇长段切分时先按句末标点切分为句子序列，再按顺序累加到上限以内；找不到句末标点时改在窗口内寻找逗号、分号或顿号，仍找不到时按固定窗口硬切。相邻片段之间保留上一个片段末尾的重叠字符数，重叠部分的起点对齐到最近的句子起始位置。识别到标题层级标记时在标题处强制开始新片段，并把标题文本作为后续片段的章节归属，标题本身不单独成为片段。片段继承其首个段落的来源标记，跨页或跨幻灯片的片段以首个段落为准
边界处理覆盖六类情形。段落序列为空或全为空白时返回空列表。单个段落字符数恰好等于上限时该段落单独成为一个片段，不触发切分；超过上限但不超过上限的两倍时按句子切分；超过上限十倍时先按固定窗口硬切，再在每个窗口内按句末标点做二次调整。重叠字符数大于等于片段上限时不执行重叠，退化为无重叠切分并记录一次参数告警，不抛出异常。孤立短段的字符数小于上限的十分之一时向后合并到下一个片段，若其已是最后一个片段则向前合并。
异常情况有三类。片段数超过单份资料 3000 个的上限时停止切分并保留前 3000 个片段，同时在结果中返回截断标记与原始片段总数，调用方把资料标记为部分处理。来源标记缺失的片段不进入出题候选集。输入中包含控制字符或不可见 Unicode 时在切分前统一清理并将字符数变化记入片段元数据。单份资料的切分耗时不超过 2 秒，以 20 万字符的解析结果为前提测量，实现时禁止在循环内做字符串拼接累加。

## 6.2 解析器调度与识别质量门禁

解析器调度的输入是文件扩展名、文件头字节、文件大小与可用解析器名称列表，输出是解析器名称与回退标记。处理规则是优先使用文件头字节判定真实格式，扩展名与文件头不一致时以文件头为准并记录一次告警；随后通过一次工具调用让模型在解析器名称列表中确认选择，模型返回的名称必须在列表内。模型的输入只有格式特征与解析器名称列表，不包含文件内容。
解析器调度的边界处理包含三项。文件头字节不足以判定格式时回退到扩展名映射，映射表覆盖五种允许格式与常见图片格式。扩展名与文件头都落在允许列表之外时直接返回失败，不进入解析阶段，与 FR-03 的接收阶段校验一起构成两道检查。模型调用超时或返回名称不在列表内时使用扩展名映射结果，回退标记写入任务记录，回退比例高于 20% 时说明工具调用的提示词需要调整。
识别质量门禁的输入是每页识别文本、同批页面文本长度序列与阈值配置，输出是质量报告，包含每页的乱码比例、有效字数、页面完整性判定、不合格原因与整体是否通过。默认阈值取三档：单页乱码比例上限为 15%，单页有效字数下限为 40 字，单页文本长度低于同批页面文本长度中位数的 30% 时判为页面不完整。乱码比例的计算口径是不可构成有效词的字符占比，实现上用连续字符与词典匹配的失败比例近似；有效字数统计中文字符与英文单词的数量；页面完整性的比较基准是同一次识别中所有页面的中位数，因此单页资料不适用该检查。处理规则是逐页计算三个指标，任一指标超限即把该页判为不合格；不合格原因取最严重的一项，优先顺序是页面不完整、乱码比例超限、有效字数不足。
边界处理有五项。识别文本为空字符串或全部为空白时乱码比例按 100% 计，该页判为不合格，原因记为页面不完整。同批页面数量为 1 时不使用中位数比较，直接按有效字数下限与乱码比例两项判定；数量小于 3 时中位数取平均值代替。重拍次数达到 3 次且该页仍不合格时不再进入重拍分支，返回最终不合格结论并提示用户改用其它导入方式。
异常情况有三类。OCR 接口超时按可重试异常处理，重试 1 次后仍超时则任务失败并保留已通过的页面结果，用户重试时只识别未通过的页面。OCR 返回的结果缺少页序信息时按提交顺序补齐页序并记录一次告警。识别结果中出现模型无法判定的版面区域时该区域按空白处理，空白区域占比超过单页面积的 50% 时该页判为不合格，原因记为版面识别失败。

## 6.3 知识点抽取与质检门禁

知识点抽取由模型产出候选，质检门禁由纯函数判定候选是否可用。抽取的输入是知识片段集合、资料类型与来源章节信息，输出是候选知识点列表，每项包含名称、简述、层级路径与来源片段标识列表。抽取按批次进行，每批不超过 40 个片段，单份资料最多 12 批，超出部分不再抽取并标注截断数量；批次按来源章节顺序切分。层级关系建立使用一次独立调用，输入是去重后的知识点名称列表与各自的来源章节信息，输出是父子关系列表；去重规则是名称规范化后相同，或名称向量相似度高于 0.92；层级深度上限为 5，超过上限的节点被提升到第 5 层。
质检门禁的输入是候选知识点列表与统计量，统计量包含知识点总数、层级深度的最大值与各层节点数分布、每个知识点名称的长度与字符构成、每个章节的片段占比与对应的知识点数量；输出是逐项得分、整体结论与不通过原因列表。四项检查的判定规则如下。数量区间检查以知识点数量与资料有效字数的比值作为依据，每 5000 字有效文本对应 1 至 8 个知识点，知识片段总数少于 20 个时要求知识点数量不少于 3 个，超过 200 个判为过度拆分。层级深度检查要求最大深度落在 2 至 5 之间，深度为 1 判为平铺，超过 5 判为嵌套过深，第 2 层节点数占总数的比例超过 60% 判为层级退化。命名可读性检查要求名称长度落在 2 至 30 个字符之间，且不包含占位词与截断痕迹，占位词表包含"知识点""内容一""其他""待补充""未命名"等条目，截断痕迹的判定是名称以省略号结尾或以半个括号结尾。章节覆盖率检查取片段占比不低于 5% 的章节作为关键章节，要求每个关键章节至少对应 1 个知识点，覆盖率低于 80% 判为不通过。四项检查各自给出结论，任意一项不通过时整体结论为不通过，不通过原因按检查项列出具体数值，例如"知识点数量 268 个，同规模资料的区间上限为 96 个"。
重抽策略最多两次。第一次重抽把不通过原因追加到提示词尾部，并降低单批片段数到 20 个；第二次重抽追加数量区间约束与命名规范，要求名称长度为 4 至 16 个字符且不包含编号。第二次重抽仍不通过时采用本次结果，把知识结构可信度标记为低，对应 FR-18 与 FR-53。
边界处理覆盖五类情形。知识片段总数为零时不执行抽取，直接返回跳过结论并把资料标记为无可用内容。候选知识点数量为零时整体判为不通过，不进入数量区间的比值检查。全部知识点的层级路径为空时按平铺处理并整体判为不通过。名称全部为单字符或全部超过 30 字符时命名可读性检查不通过。同一章节的片段占比恰好等于 5% 时按关键章节处理。异常情况有三类。模型返回的知识点名称与片段标识不匹配时该条目被丢弃并计入任务记录，丢弃比例超过 30% 时整体判为不通过并触发重抽。同一批次的模型调用连续两次返回结构不合法时该批标记为抽取失败。重抽过程中资料被用户删除时任务终止并记录终止原因，不写入任何知识点。

## 6.4 题目质检算法

题目质检在题目进入练习之前拦下四类不可用题目。输入是候选题集合、每题的来源片段内容、题干与选项向量、同一资料下已通过质检的题目集合与阈值配置，输出是保留题目集与逐题剔除原因，剔除原因限于四类之一。重复题检查取题干与选项组合向量的最大余弦相似度，向量相似度高于 0.90 或字符级相似度高于 0.85 判为重复题。答案冲突检查在题干相似度高于 0.88 的已有题目之间逐项比对标准答案集合，标准答案不同的判为答案冲突，客观题按选项标识集合比对、顺序不同视为相同，主观题不做该项检查。无来源检查覆盖两项判定：来源片段标识缺失或指向的片段不属于当前资料时判为无来源；来源片段存在但题干中的实词在来源片段中的出现比例低于 0.30 时同样判为无来源。
歧义检查按题型区分。单选题的正确答案数量必须恰为 1，多选必须至少 2 项且不超过选项总数减 1，判断题的答案必须为二值。选项集合中存在内容重复的选项、选择题的正确选项数等于选项总数、填空题的答案集合为空三种情形判为歧义。题干中出现"以上都对""以上都不对"且同时存在其它正确选项时判为歧义。题干长度少于 6 个字符时判为歧义。四类检查按无来源、重复题、答案冲突、歧义的固定顺序执行，一道题同时命中多个条件时原因取顺序最靠前的一项。检查失败的题目进入待处理区并保存剔除原因与生成批次号，不进入练习，也不计入正确率与掌握度计算，对应 FR-25。
边界处理有五类。候选题集合为空时返回空集合与空原因列表，不报错。同一题干在同一批次内出现多次时保留生成时间最早的一道。来源片段内容为空字符串时按无来源处理。向量计算不可用时跳过指纹类检查，只保留无来源与歧义两类检查，并在质检结论中标注检查项不完整。相似度恰好等于阈值时按重复处理。异常情况有两类。同一资料下已有题目数量超过 500 道时重复题检查的比对范围截取最近 500 道，比对范围写入质检结论。质检配置中阈值取值非法，例如下阈值大于上阈值或阈值不在 0 至 1 区间内时，质检模块返回参数错误而不使用默认值静默执行。

## 6.5 混合判题与阈值策略

混合判题的共同点是最终得分与结论都由纯函数给出，模型只提供语义评分与要点判断。客观题判分的输入是题目类型、标准答案、用户答案与判分配置，输出是得分、对错标记与判分依据；单选题比对选项标识，多选要求正确选项集合完全一致，判断题比对二值结果；填空题在比对前执行答案规范化，涵盖去除首尾空白与内部多余空白、全角转半角、英文字母统一小写、中文数字与阿拉伯数字归一四项；同一空存在多个等价答案时任一命中即为正确，空答案统一判为错误并标记为未作答，对应 FR-38。
主观题离线判分的输入是用户答案文本、评分细则要点列表及权重、关键词表、否定词表、语义相似度上下阈值，输出是匹配度、命中要点列表、遗漏要点列表与是否转 AI 判题的标记。匹配度由要点覆盖率与语义相似度两部分合成。要点覆盖率的计算方式是逐条判断要点是否被命中，命中判定为要点中的关键词在用户答案中至少命中 60%，且该要点相关的否定词不出现，命中要点的权重之和除以全部要点权重之和得到覆盖率；语义相似度取用户答案向量与参考答案向量的余弦相似度。合成公式为匹配度等于要点覆盖率乘以 0.6 加语义相似度乘以 0.4，权重如此分配的理由是评分细则由模型生成，要点质量的稳定性低于语义相似度，避免要点生成失误直接决定判分结论。
阈值取值与区间定义如下。匹配度上阈值取 0.82，达到或超过该值时按离线判对处理，得分按题目分值乘以匹配度并按 0.5 分的粒度四舍五入；下阈值取 0.45，低于该值时按离线判错处理；落在 0.45 与 0.82 之间属于不确定区间，转 AI 判题。两个阈值的取值依据是项目组在样本答卷上的试算结果：上阈值取 0.82 时，语义正确但措辞差异较大的答案有 12% 落入区间并转 AI，离线判对的准确率保持在 95% 以上；下阈值取 0.45 时，明显错误但包含少量正确关键词的答案不会被离线判对。边界取值的约定是恰等于下阈值按离线判错处理并进入转 AI 判定，恰等于上阈值按离线判对处理，三个边界各有独立测试用例。
转 AI 判题的条件有四类，满足任一即转入。第一类是离线判为错误，这条条件覆盖面最广。第二类是匹配度落在不确定区间。第三类是题目在生成时被标记了多个等价表达，离线规则无法区分这些表达。第四类是用户答案的要点覆盖率为零但语义相似度高于 0.55，判为无法严格匹配。四类条件的判定全部在纯函数中完成，函数返回布尔标记与命中条件的编号，服务层按标记决定是否发起模型调用。
AI 判题的调用约束有四项。输入包含题目、参考答案、评分细则与来源片段，不包含用户身份信息与资料标识；超时时间设为 20 秒，单题最多调用两次；返回结构用 Pydantic 模型校验；置信度低于 0.5 时服务层在结果中标注重判题可信度较低，用户可以选择自评覆盖。降级路径按三种失败形态定义：模型调用超时、返回结构不合法、网关返回不可重试错误，三种情况下该题均标记为待重新判题，答案完整保留，也不把题目判为错误，对应 FR-42。用户选择自评时，自评结果保存为独立判题结果，来源标记为用户自评，掌握度权重按 0.5 计算，对应 FR-43。
边界处理有六类。用户答案为空字符串或全部为空白时，客观题判为未作答，主观题直接判为未作答并跳过离线匹配，不消耗模型调用。用户答案长度超过单题上限 2000 字时截取前 2000 字参与匹配并标记答案被截断。用户答案与参考答案完全一致时匹配度按 1.0 处理，跳过模型调用。评分细则为空的主观题直接转 AI 判题。否定词表命中且要点关键词同时命中时，该要点的命中判定取反，否定词的作用范围按关键词所在的分句界定，跨分句不传播。待重新判题的题目重新判题成功后，结果更新为 AI 判题来源，掌握度按新结果重新计算，对应 FR-46 与 FR-47。

## 6.6 掌握度计算

掌握度计算的输入是某知识点下该用户的答题记录序列、当前时间与权重配置，每条记录包含对错标记、作答时间、题型、判题来源与分值；输出是 0 至 1 的掌握度数值与四档档次。函数不访问数据库，不调用外部服务，当前时间由调用方作为显式入参传入，相同输入与相同时间重复调用得到完全相同的结果，对应 FR-47 与 NFR-23。计算由三步组成。第一步按判题来源取权重：离线判题取 1.0，AI 判题取 0.8，用户自评与待重新判题取 0.5，因为判题来源决定记录的可靠程度，让三类记录对掌握度施加同等影响会让不确定的判分主导数值变化。第二步按作答时间远近取时间衰减因子，形式为以自然常数为底的指数函数，指数为衰减系数乘以距当前时间的天数再取负值；衰减系数默认取 0.023，对应的半衰期约为 30 天。第三步合成加权正确率。公式形式为：掌握度等于对全部记录累加（结果标记乘来源权重乘时间衰减因子）除以对全部记录累加（来源权重乘时间衰减因子）。
结果标记取答对为 1、答错为 0.2、未作答为 0，答错取 0.2 而不是 0 是避免掌握度因为一次失误直接归零，未作答取 0 是因为未作答不提供任何关于掌握程度的信息。参与计算的记录限定为该知识点下按作答时间倒序的最近 200 条有效答题记录，待重新判题的记录不参与计算；200 条的上限依据是数据规模假设中单用户累计答题记录不超过 5 万条，200 条足以覆盖一个知识点在三个月内的作答密度。
四档切分规则如下。没有有效答题记录时档次为未学，数值返回 0；数值大于 0 且小于 0.40 时为薄弱；大于等于 0.40 且小于 0.70 时为基本掌握；大于等于 0.70 时为熟练。切分点取 0.40 与 0.70 的理由是这两个点把答对一次的基础状态与稳定答对的状态分开：单次答对的基础状态按 30 天衰减后落在基本掌握区间内，长期未复习回落到薄弱区间，连续答对三次以上的状态进入熟练区间；两个切分点通过配置项管理。
边界处理覆盖六项。答题记录序列为空时返回数值 0 与未学档次。全部记录为答错时数值等于 0.2 乘以时间加权平均，档次落在薄弱。有效记录数量少于 3 条时有数值但报告在结论位置标注样本量偏小。折旧后的总权重小于 0.05 时按未学处理。答对记录集中在最近 7 天内且数量不少于 3 条时数值不会低于 0.70。全部记录的来源都是待重新判题时返回数值 0 与未学档次。异常情况有三类。答案记录的对错标记缺失时该条记录被丢弃，丢弃数量写入计算结果元数据。衰减系数被配置为非正数时函数返回参数错误而不使用默认值。时间衰减因子的指数绝对值超过 700 时按计算机浮点下溢处理，因子取 0，该条记录实际不参与合成，不抛出溢出异常。掌握度更新的时机有两处：判题任务完成后立即更新一次，对应第 3.2.5 节的第 1 步至第 4 步；用户触发待判题目的重新判题并成功后再更新一次，更新范围限于该题涉及的知识点。两处更新都写入掌握度快照，快照用于计算下一次练习的退步知识点。

## 6.7 诊断规则合成

诊断规则合成把统计结果转成结论表述，本身也是无副作用的函数。输入是本次练习涉及知识点及其掌握度、上一次练习的掌握度快照、本次练习的题型分布、未作答数量、判题来源统计与知识结构可信度标记，输出是报告的四部分内容。主要薄弱知识点的选取规则是按掌握度从小到大排序取前 3 项，每项必须关联至少一条本次练习中的答错记录；全部知识点都没有关联答错记录时返回空的薄弱清单，并在报告中标明本次练习未发现明确薄弱项，不给出薄弱结论，对应 FR-50。
退步知识点的判定规则是逐个知识点比较本次快照与上次快照的掌握度数值，本次数值低于上次数值且差值不小于 0.05 时判为退步，本次练习中新出现的知识点不计入退步统计；差值下限取 0.05 的理由是掌握度数值的合成包含浮点运算与参数取值，小于该幅度的变化难以与计算抖动区分。可能原因的合成采用规则表驱动，输入条件与输出表述的对应关系固定，不调用模型。规则表包含五条主要规则：主观题要点命中率低于 0.40 而客观题正确率不低于 0.70 时，原因指向表述与要点组织；未作答数量占本次题目总数的比例高于 0.20 时，原因指向作答时间不足；AI 判题来源的题目占比高于 0.50 时，原因指向题目表述与资料原文的差异；某知识点的答错记录集中在同一题型时，原因指向该题型的能力欠缺；全部知识点的掌握度均低于 0.40 且题目正确率低于 0.40 时，原因指向基础知识尚未建立。多条规则同时命中时按固定顺序取前两条。
下一步建议由薄弱知识点清单与规则的输出共同决定，建议内容落实到具体知识点名称，并与报告末尾的继续练习入口覆盖的知识点集合一致。知识结构可信度标记为低时，报告首部增加一段说明，指出知识结构经三次抽取仍未通过质量检查，报告中的薄弱知识点划分可能不准确，建议用户结合原文核对。边界处理有三类。本次练习涉及的知识点数量为 1 时，报告直接给出该知识点的结论与建议。历史答题记录不足时报告在结论位置标注样本量偏小并给出已积累的记录数量。判题来源统计中待重新判题的题目数量大于零时，报告标注待判题数量并说明该部分题目暂不计入结论，用户重新判题后可以重新生成报告。

# 7 可测性设计

本章说明系统为可测试性所做的设计安排，以及这些安排如何在测试活动中被使用。可测性在本项目里不是附加要求，需求文档 NFR-22 至 NFR-25 把它写成必须满足的验收条件：分块的边界取值、质检的判定组合、阈值区间的开闭、掌握度的时间衰减，这些行为在人手操作中几乎不可观察，只能靠构造输入的自动化用例覆盖。本章的算法清单与代码管理文档第 4.2 节的必测纯函数计算核完全一致，两份文档的表述不得出现差异。

清单之外还有三个辅助函数模块参与核心计算，它们不单独列为必测计算核，但一并纳入算法层的单元测试范围。答案规范化函数处理填空题答案的空白、全角半角、大小写与数字格式四项归一，用例以成对输入的形式组织。档次映射函数处理掌握度数值到四档档次的映射，用例覆盖两个临界值的上下相邻取值。相似度合成函数处理要点覆盖率与语义相似度的加权合成，用例以桩替换语义相似度输入并固定权重配置。
判题阈值与匹配这一块的测试重点在不确定区间的边界：相似度落在下阈值与上阈值之间时转 AI 判题，恰等于下阈值按离线判错处理，恰等于上阈值按离线判对处理，三个边界各有独立用例。否定词的用例需要覆盖仅有否定词不同、其余文字完全一致的成对输入，验证两者得分方向相反。掌握度计算的默认衰减系数取 0.023，权重方面离线确定判分取 1.0、AI 判题取 0.8、用户自评与待重新判题取 0.5，用例覆盖闲置 3 天、7 天、30 天与 300 天四种情形。
白盒度量按测试报告的要求执行。对上述五块计算核绘制控制流图，按环路复杂度等于边数减节点数加二、也等于判定节点数加一的关系计算复杂度，并依据独立路径集设计用例，保证每条独立路径至少执行一次。资料分块算法的主切分函数、判题匹配函数与掌握度聚合函数作为重点对象，目标是把环路复杂度分别控制在 12、10 与 8 以内，超过时先做函数拆分再补齐用例。

## 7.2 外部依赖隔离与 Mock 方案

系统有三类外部依赖：OCR、大语言模型与向量化能力，以及对象存储与任务队列。前一类是外部服务，后一类是基础设施；两类依赖的隔离方式不同，前者通过协议接口加可替换实现，后者通过容器化依赖加事务隔离，具体替换方式见表 7-2。
表 7-2　外部依赖隔离与替换方式
| 依赖 | 接口形态 | 单元测试替换方式 | 集成测试替换方式 |
| --- | --- | --- | --- |
| OCR 识别 | 协议接口，输入图片字节流，输出分页文本与版面块 | 固定返回值的桩实现，可注入延迟与错误码 | 容器内使用真实接口，超时场景通过延迟开关模拟 |
| 大语言模型 | 协议接口，输入消息序列与工具定义，输出结构化结果 | 固定返回值的桩实现，覆盖结构合法与结构残缺两种返回 | 容器内使用真实网关，超时与限流场景通过注入开关模拟 |
| 向量化 | 协议接口，输入文本列表，输出定长向量列表 | 返回固定向量的桩实现，向量由文本长度与字符编码派生，保证同文本同向量 | 使用真实向量化接口，或在容器内加载本地小模型 |
| 对象存储 | 协议接口，输入对象键与数据流，输出引用与摘要 | 内存实现，用例结束丢弃全部对象 | 使用容器化的对象存储，每个用例使用独立桶并在结束时删除对象 |
| 任务队列 | 协议接口，输入任务名与载荷，输出任务标识 | 内存队列实现，支持同步立即执行模式 | 使用容器化 Redis，每个用例使用独立库编号并在用例前清空 |

隔离方案有三条实现要求。协议定义放在外部能力适配目录下，业务代码只导入协议类型，不导入供应商 SDK 的客户端类型与异常类型，对应 NFR-26。桩实现与真实实现注册在同一个依赖装配位置，测试通过配置项切换实现，不在业务代码中出现"如果是测试环境就用桩"这类分支。超时与重试逻辑写在适配层内部，算法层与服务层只感知适配层抛出的统一异常类型。
单元测试的边界由三条规则划定。单元测试不连接数据库、缓存与外部服务，单个用例执行时间在毫秒级，全部单元测试在 30 秒内跑完。需要替身的只有三类对象：外部能力适配器以固定返回值的桩实现替换；时间与随机数以可注入的时钟与固定种子替换；对象存储与队列以内存实现替换。禁止对被测函数自身的内部调用做断言。
集成测试的环境隔离做法如下。数据库每个测试会话建一次结构与向量扩展，每个用例在事务中执行并在结束时回滚。缓存使用独立编号的库并在每个用例前清空；对象存储使用临时桶，用例结束删除对象。外部能力一律替换为固定返回的假实现，需要模拟超时的场景通过注入延迟开关实现。测试进程内禁止真实联网，出现外部连接即抛错，避免慢测试与不可控的费用。

## 7.3 测试分层与覆盖目标

测试分为单元、集成、接口与端到端四层，另加独立执行的性能测试。用例数量分布按金字塔要求控制：单元测试占六成以上，集成与接口测试合计约三成，端到端用例控制在一成以内。
各层的覆盖对象与判定标准如下。单元测试覆盖第 7.1 节清单中的五块计算核与三个辅助函数模块，判定标准是全部用例通过且算法模块的行覆盖不低于 95%、分支覆盖不低于 90%。集成测试覆盖数据访问层的查询与写入、向量检索、队列投递与消费、对象存储读写。接口测试覆盖鉴权、参数校验、错误码、分页与幂等，必须包含五类行为：未携带令牌访问受保护接口返回 20001；使用甲用户令牌访问乙用户资料返回 20002 或不返回内容；资料落库对零字节文件、超过 50 MB 文件、扩展名与内容不符文件分别返回对应错误码；重复提交同一幂等键返回首次结果且不产生第二条记录；分页参数越界返回参数校验失败。端到端测试覆盖导入资料、查看出题进度、作答与交卷、查看判题结果、查看诊断报告并继续练习五条关键路径。
全局覆盖目标与分模块目标沿用代码管理文档第 4.3 节的规定，全局行覆盖不低于 80%、分支覆盖不低于 70%，关键模块适用更高阈值。偏离阈值的例外必须走评审，在改动说明中写明被排除的行数、理由与替代验证方式。覆盖率不是唯一门槛，覆盖率上升但用例集中在取值简单的路径上时，需要补充边界与异常路径用例。本节清单与代码管理文档第 4.2 节的必测纯函数计算核清单保持逐项一致；两份文档中任何一份调整清单时，必须在同一次改动中更新另一份。

# 8 安全设计

本章描述系统的安全设计。安全要求在本项目里以数据归属为核心；次要目标是资料内容与用户答案在存储、传输与对外调用过程中不被非授权方获取。本章说明鉴权与用户隔离、文件校验与越权防护、日志隐私与密钥管理三个方面。

## 8.1 鉴权与用户隔离

登录采用微信授权方式。小程序端调用微信授权接口取得临时凭证，服务端用该凭证换取用户唯一标识，首次登录时创建用户记录。服务端签发访问令牌与刷新令牌，访问令牌有效期 2 小时，刷新令牌有效期 30 天并在每次使用时轮换。令牌使用非对称签名，签名私钥保存在服务端配置中；令牌负载中只包含用户标识与过期时间，不包含资料标识与其它业务信息。
数据隔离的实现口径是把归属校验集中在服务层。所有涉及用户数据的查询必须以用户标识作为首个过滤条件，用户标识从服务端登录态中取得；接口入参中出现的用户标识一律忽略并记录异常事件，不作为查询条件。涉及子实体的查询通过连接回到所属资料或所属练习再校验用户标识，不接受"客户端传了资料标识就认为是本人资料"的写法。数据访问层不提供不带用户条件的查询方法。
令牌失效与注销的处理有两种情形。访问令牌过期时由刷新接口换取新令牌，刷新令牌过期时用户需要重新授权。用户删除账号时全部令牌立即失效，失效通过令牌版本号实现：用户记录上保存一个版本号，令牌负载中携带签发时的版本号，版本号不匹配时判定令牌失效。

## 8.2 文件校验与越权防护

文件校验分三层，全部在接收阶段完成，不放到解析阶段，对应 FR-03。第一层校验文件大小，落在 1 KB 至 50 MB 之外的文件直接拒绝并返回实际大小与允许区间。第二层校验扩展名与文件头，扩展名必须在允许列表内，文件头字节必须与扩展名所声明的格式一致，不一致时拒绝并说明实际识别的格式。第三层校验文件内容，带打开口令的文档、结构损坏的文档、内容摘要命中已有版本的文件分别按加密、损坏、重复三类情形处理，其中加密文件返回错误码 40001。
把校验前置的原因是可测性与资源保护两方面的。无效文件进入队列会消耗解析资源，失败信息还会混在解析失败的原因里。校验放在接口层的独立函数中实现，该函数是纯函数，输入文件头字节的前 512 个字节、扩展名与文件大小，输出判定结果与拒绝原因，可以被单元测试完整覆盖，包括零字节、超大与伪造扩展名三种典型输入。
越权防护的检查点有四处。对象存储的访问凭证按资料标识签发，凭证中限定对象键前缀与有效期，用户无法通过猜测对象键读取他人文件。向量检索强制带资料标识与用户标识条件，避免通过相似度检索跨用户召回片段。题目与答卷的读取校验归属，跨用户访问返回错误码 20002 且响应体不含内容片段。删除操作校验归属，删除他人资料返回 20002。
用户删除资料与账号的操作按逻辑删除加物理清理实现。逻辑删除后所有访问路径立即不可达，物理清理任务每天执行一次，清理七天前的已删除记录与对应的对象存储文件。资料删除时其派生的片段、向量、知识点、题目与质检记录一并删除，已有答卷中的作答记录保留题目内容快照与判题结果。

## 8.3 日志、隐私与密钥管理

日志使用结构化输出，每条至少包含时间、级别、日志名、请求标识、用户引用、业务对象标识、耗时与错误码；用户引用只记录用户标识的不可逆摘要前八位。日志级别按用途划分：INFO 记录任务创建、状态流转、判题完成等关键业务节点；WARNING 记录 AI 判题超时转待重新判题、外部调用重试等可恢复异常；ERROR 记录需要人工介入的失败；DEBUG 只用于本地开发，不进入测试与生产环境。
日志禁止记录五类内容：学习资料全文、题目与参考答案全文、用户作答原文、访问令牌与刷新令牌、明文用户标识。排查文本相关问题时记录长度、片段数量、匹配度、判分来源这类可量化字段即可。写入日志前统一经过脱敏函数，脱敏规则变更必须有对应测试用例。发送给 OCR 与语言模型的请求不附加用户身份信息与账号信息，模型调用的请求与响应不落全文日志，只记录调用类型、耗时、返回结构是否合法与失败原因，对应 FR-63、FR-64 与 NFR-16。
资料内容与答题数据默认不用于训练模型。调用外部能力时对资料内容的使用范围限于本次任务，提示词中不包含用户的其它资料内容。这一点在界面上以说明文字告知用户，用户可以在设置位置查看，对应 NFR-17。
密钥管理按四类分开。数据库口令、缓存口令、对象存储访问密钥、外部能力密钥全部通过环境变量注入，环境变量样例文件随仓库维护但只放占位值，真实值由部署环境提供，不进入仓库，对应 NFR-15。登录令牌的签名私钥单独管理并支持轮换：轮换时新旧私钥同时有效一段时间，已签发的令牌在有效期内仍可验证。密钥的读取集中在配置模块中，业务代码不直接读取环境变量；密钥变更属于部署配置类改动，需要双人评审并附回滚步骤。

# 9 部署与运维设计

本章描述系统的部署形态、环境划分、配置管理、备份策略、监控告警与回滚流程。部署设计需要照顾两个现实条件：四人小组没有专职运维，因此运维动作必须可脚本化、可重复执行；外部能力的存在意味着线上问题可能来自系统之外，监控必须能区分本系统的问题与外部服务的问题。

## 9.1 容器编排与运行参数

部署单元与参数在第 3.1 节已经给出拓扑。全部服务通过一个 compose 文件描述，服务之间通过内部网络通信，只有接入层暴露宿主机端口。容器镜像使用固定的基础镜像摘要，不在部署时执行依赖安装。接口服务与任务消费者共用同一镜像，通过启动参数区分。
健康检查分三层。容器层面检查进程是否存活，接口服务检查 /health 路径是否在 2 秒内返回成功，任务消费者检查上一次心跳时间是否在 60 秒内。部署脚本在替换容器时等待健康检查连续通过三次才认为该容器就绪，未就绪时中止替换并保留旧容器运行。数据库容器的健康检查包含一次简单查询。
资源限制按容器设置。接口服务的 CPU 上限为 2 核、内存上限为 2 GB，任务消费者的 CPU 上限为 2 核、内存上限为 3 GB，数据库的 CPU 上限为 2 核、内存上限为 4 GB，缓存与对象存储各 1 GB。设置上限的目的是防止单个大文件解析耗尽整机内存，导致接口服务不可用；超出内存上限的容器被系统终止并由编排层重启，重启次数在监控中体现。

## 9.2 环境划分与配置管理

环境划分三套，第 3.1 节已给出差异项。配置项分为三类管理。第一类是可公开的默认值，例如分页条数、字体与界面文案，写在代码仓库的配置文件中。第二类是影响行为的阈值参数，包括判题匹配度上下阈值、分块长度与重叠、识别质量阈值、质检阈值、掌握度衰减系数与档次切分点、题数范围、文件大小上限，全部通过配置项管理并支持在不重新发布的前提下调整，对应 NFR-28。第三类是密钥与连接串，只通过环境变量注入。
第二类配置项的调整需要留痕。每个阈值配置项在数据库配置表中保存当前值、生效时间、调整人与调整原因，调整动作记录到运维日志。阈值调整不得与业务代码改动混在同一次发布中。配置项集中由配置模块读取，模块在启动时校验取值合法性，例如上下阈值的大小关系、衰减系数为正、档次切分点递增，校验失败时拒绝启动并把非法项写入日志。
调试开关的适用范围受限制。系统保留三个开关：外部能力桩模式、任务同步执行模式、详细日志模式。三个开关在测试环境可以随时切换，在生产环境不开放。

## 9.3 备份、监控与回滚

备份按三类数据分别安排。数据库采用每日全量加每小时增量日志的方式，全量备份保留 14 天，备份文件写入独立的备份机器并校验摘要，恢复演练每月执行一次。对象存储的资料原件按每周一次的增量同步到备份机器，同步以版本为粒度，已清理版本的备份同步删除。配置与密钥的备份保存为加密文件，与数据库备份分开存放，恢复时需要有相应的解密密钥。
监控指标分四组。业务指标包括任务成功率、任务平均耗时、各类任务积压深度、出题成功率、判题来源分布比例、待重新判题题目数量。外部能力指标包括 OCR、语言模型与向量化的调用次数、失败次数与耗时分布。系统指标包括接口 95 分位响应时间、接口错误率、数据库连接数与慢查询数量、缓存命中率、容器内存占用。安全指标包括越权访问尝试次数、令牌校验失败次数、参数校验失败次数。任何指标从监控中消失的时间超过 5 分钟，按服务异常处理，对应 NFR-27。
告警阈值按可执行的标准设置。接口错误率连续 3 分钟高于 1% 时告警。任一任务队列积压深度超过 200 时告警。OCR 或语言模型调用失败率连续 5 分钟高于 5% 时告警，这类告警在通知中标注为外部服务问题，与自身故障区分。接口 95 分位响应时间连续 5 分钟超过 3 秒时告警。数据库连接池使用率超过 80% 时告警。告警只对需要人工介入的情况发送，可自愈的重试与退避不产生告警，避免告警疲劳。
回滚分两条路径。代码与配置问题直接切回上一版本镜像，回滚耗时目标为 2 分钟以内。涉及数据库结构变更的回滚必须使用迁移脚本的降级路径，降级前先备份受影响的表，不可逆的迁移在发布说明中标注为不可降级并要求在部署窗口内完成数据校验。部署脚本要求幂等，重复执行不产生额外副作用，脚本中不硬编码口令与地址。
发布流程按四步固定执行。拉取目标镜像并核对标签与提交标识的对应关系；执行数据库迁移，迁移失败时中止部署并保留旧容器运行；以滚动方式替换后端服务，健康检查连续通过三次后视为该服务部署成功；更新部署记录，写入版本号、提交标识、执行人与时间。小程序端的发布与服务端解耦，服务端提供兼容接口，避免用户端未更新导致主链中断。

# 10 设计约束与待确认项

本章列出尚未解决的设计问题与已经确定的设计约束。把未解决的问题写进交付文档的目的是让下一阶段的负责人知道哪些地方还需要验证、验证的判据是什么。每条待确认项给出待确认内容、当前取值、确认方式与责任人四项信息；当前取值表示设计上已经按该值实现，确认方式表示如何验证该取值是否需要调整。
约束方面有六条已经确定并且不允许在实现阶段自行放宽。第一，外部能力一律通过协议接口调用，业务代码不导入供应商 SDK 的类型，对应 NFR-26。第二，五块纯函数计算核不导入数据库驱动、HTTP 客户端与缓存客户端，依赖方向由脚本检查，对应 NFR-22。第三，出题前必须检索到来源片段，检索不到时拒绝出题，不接受先生成再补来源的做法，对应 FR-21。第四，AI 判题失败或超时时题目停在待重新判题状态，不得直接判为错误，对应 FR-42。第五，掌握度计算不读取系统时钟，当前时间由调用方传入，对应 FR-47。第六，判题与质检的阈值参数通过配置项管理，不在业务代码中硬编码默认值，对应 NFR-28。
