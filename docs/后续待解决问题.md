## 一、阻塞项：主链路上的功能缺陷（均已定位根因，未开工）

这四条的共同特征是：**用户卡住之后，系统什么都不说**。它们不是「不好用」，是「用不了」。

### P0-1 解析流水线卡死且不可恢复

| 项 | 内容 |
| --- | --- |
| 现象 | 上传资料后永久停在「正在抽取考点拓扑」，无按钮、无提示、无失败 |
| 实测原话 | 「我有一个一小时前上传的文件，一直在解析，没有返回资料」 |
| 根因 | 已复现并定案：后端缺重派通道、前端缺超时反馈与逃生入口 |
| 已修部分 | **worker 在 Windows 上不可用**这一子项已修复（`6c3ffcd` 改用 `SimpleWorker`、`6b9832c` 改用 `TimerDeathPenalty`） |
| 仍缺部分 | 陈旧版本重新入队通道、与 /parse 并发保证不冲突的判定、前端重试入口，以及「排队超时」与「后台解析服务未运行」两种状态的区分 |
| 完成度 | 该任务的验收项（AC-0 ~ AC-9）**全部未勾**，端到端确认未做 |
| 影响 | **阻断性**。主链路第 1~3 节点全部走不通，后续所有现象都无法归因 |
| 下一步 | 前后端各修一半：后端补重派，前端补超时提示与「重试 / 删除」出口。**只修一侧用户依然卡死** |
| 任务 | `.trellis/tasks/09-29-fix-parse-stuck/` |

验收要点：链路上任何一种「卡住」都必须**可诊断、可恢复、有出口**——
不允许存在「用户什么都做不了、系统什么都不说」的静止状态。

### P0-2 思考模式模型上结构化输出不可用

| 项 | 内容 |
| --- | --- |
| 现象 | 换用 DeepSeek 官方 API 后，所有出题 / 知识点抽取调用返回 502（底层 400） |
| 根因 | 强制 `tool_choice` 与思考模式不兼容。已有修复提交 `d0e759b`（不再强制 `tool_choice`） |
| 完成度 | 任务的 AC-7「端到端待用户确认」**仍未勾**——修复未经真实生题验证 |
| 影响 | 出题、抽取、主观题判题三条链路全部依赖大模型结构化输出 |
| 下一步 | 补齐端到端确认（重启后端后在开发者工具里完成一次真实生题）；换多个供应商各跑一轮并纳入回归 |
| 附带发现 | `LLMError.details` 里已带 `status_code` 与 `body[:200]`，但 HTTP 响应只透出「异常状态码: 400」，**上游真实原因在接口层被丢掉**，导致排查必须走「复现 + 打点」。修它涉及错误响应的对外契约，未顺手改 |
| 任务 | `.trellis/tasks/09-29-fix-llm-thinking-mode/` |

### P1-3 出题链路没有反馈

| 项 | 内容 |
| --- | --- |
| 现象 | 点「一键智能出题」后屏幕上什么都看不到，不知道题目在哪 |
| 根因 | `questions/index.vue` 的 `isConfigMode` **没有任何一处被写成 `false`**，预览区（生成的题目、覆盖缺口、「开始作答」）是不可达的死代码 |

| 仍缺部分 | 验收项 AC-6「**「开始作答」在全流程中可达**」未勾 |
| 下一步 | 补齐「生成中 / 生成失败 / 生成成功但零题」三态反馈，并打通核对页到作答会话的落点 |
| 任务 | `.trellis/tasks/09-29-fix-qgen-feedback/` |

### P1-4 个人页学习足迹统计口径漏算

| 项 | 内容 |
| --- | --- |
| 现象 | 「我的 → 学习足迹」显示为 0 |
| 根因 | 统计**只对课程级聚合求和**，`folder_id IS NULL` 的资料被静默排除。用户持有 4 份 `ready` 资料，统计最多只算 1 份 |

| 下一步 | 修聚合口径；同时区分「没有数据」与「拉取失败」两种空态（与 P2-6 同源） |

## 二、会误导用户的功能缺陷

### P1-5 举一反三高估覆盖率

| 项 | 内容 |
| --- | --- |
| 现象 | 错题知识点超过 10 个时，界面可能**声称某考点已覆盖，而那道题根本没进练习** |
| 根因 | `regenerateFromWrongPoints` 按「全部生成题目」算覆盖率，而后端显式题目路径按 `question_count` 切片（默认 10） |
| 影响 | 用户相信系统说「已覆盖」，于是不再练那个考点 |
| 为什么现在更要紧 | 手动标记错题上线后，更多错题会走这条链路，**可见面变大了** |
| 下一步 | 覆盖率按**实际进入练习的题目**计算，而不是按生成结果计算；补防回归测试并做变异验证 |
| 任务 | `.trellis/tasks/09-29-question-bank-tab/`（F6 / R6） |

### P1-8 题库区块进入页面不自动加载，且空态文案会说谎

| 项 | 内容 |
| --- | --- |
| 现象 | 「学情」页的**「我的题目」永远显示「题库还是空的」**，即使用户已经生成过题目 |
| 位置 | `miniprogram/src/pages/review/components/QuestionBankSection.vue` |
| 根因 | `loadBatches` 在该组件内**只有 `@tap` 引用**（「刷新」与「重试」两个按钮），**没有任何程序化调用点**；组件内也**没有任何生命周期钩子**（无 `onMounted` / `onShow` / `onActivated` / `watch`）。因此进入页面时根本不会发起请求 |
| 数据侧反证 | 接口 `/questions/batches` 实测 `HTTP 200`，返回 **2 个批次**（8 题与 13 题），`total=2`；数据是存在的 |
| 界面侧反证 | 该区块渲染的是**空态**（`batches.length === 0` 分支）而不是失败态（`loadError` 分支），说明请求要么没发出、要么返回了空——与「没有调用点」一致 |
| 为什么危险 | 空态文案写着「题库还是空的。到资料详情页发起『智能出题』」。用户明明出过题，界面却让他**再去出一次**——这不是「没显示」，是**在误导用户重复劳动** |
| 为什么测试没拦住 | `miniprogram/tests/questionBank.spec.ts` 有 16 个用例，测的是 `useQuestionBank` **组合式函数**的行为；而缺陷在**组件与组合式函数之间的接线**上。用例全绿，功能不可用 |
| 下一步 | 在组件挂载或页面可见时调用 `loadBatches`；补一条**断言它会被自动调用**的接线测试（现用例如按「存在即验证」的思路写，不会红） |
| 待核实 | 手动点「刷新」是否能加载出来——自动化点击未观察到界面变化，尚不能确认该按钮是否有效 |

**这条与 `docs/开发过程文档.md` 5.3 节记的是同一类错误**：被测单元正确，不等于接线正确。
「组合式函数全绿」与「覆盖率达标」都不能替代**端到端确认**。

## 四、需要单独决策的设计问题

### D-1 客观题是否改为交卷时同步判

| 项 | 内容 |
| --- | --- |
| 现状 | 交卷后判题**全部异步入队**，包括本该毫秒出结果的客观题 |
| 用户感受 | 「选择题也要判题，不该秒出么」 |
| 澄清 | 用户实测时 worker 不可用，所以所有题停在「判题中」——那不是「判得慢」 |
| 但 | worker 恢复后**仍存在秒级异步延迟** |
| 需要决定 | 客观题改为交卷时同步判、只把主观题入队？还是保持全异步但优化反馈？ |

这是一条**产品与架构的取舍**，不是缺陷修复，需要单独评估后再立项。

## 五、工程质量问题

### E-1 墙钟微基准断言会抖动

| 项 | 内容 |
| --- | --- |
| 现象 | `backend/tests/unit/core/algorithms/` 下 4 处墙钟阈值断言（200 / 50 / 20 / 100 ms），全量套件在 CPU 争用下失败，**单独跑全过** |
| 性质 | 既有的**测试设计问题**，与具体改动无因果关系 |
| 已采取的措施 | 写进 `AGENTS.md`：**不放宽阈值、不把它当回归去追**——放宽阈值是把测试改到通过，不是修问题 |
| 为什么必须修 | 一个会随机变红的门禁，会让**真正的回归淹没在噪音里**，团队会开始习惯性忽略失败 |
| 下一步 | 改为相对基准或标记为性能基准单独跑；不要在 CI 里当正确性断言 |

### E-2 退出码与覆盖率都会骗人

已沉淀为质量纪律（见 `docs/开发过程文档.md` 第 4.6 节）：

- 退出码 1 背后可能**没有任何结论**（如 `lint-imports` 在 GBK 控制台上的假失败）；
- 覆盖率数字可能被排除清单抬高，排除项必须集中登记、逐项写明理由。

下一步：在 CI 中显式校验排除清单未被扩大。

## 六、明确不做与延期

### 永久排除（本期与后续都不做）

院校教务系统 / 学籍对接 · 教师端与班级管理 · 实时在线授课组件 ·
商业化付费与交易闭环 · 公共社交广场与社区 · 独立多级人工审核后台。

依据：本系统定位于**轻量级、个人化**的智能自主学习辅助工具。

### 延期到 P1 / P2 里程碑

复杂公式与图表的高精度渲染 · 多模态语音作答与判题 · 第三方题库批量导入导出 ·
协作式组队练习与 PK 竞速 · 跨资料全局知识图谱交叉融合。

### 平台与能力边界（本期约束，非缺陷）

- 客户端仅面向**微信小程序原生端**，不交付 Web PC 端或 iOS/Android 原生 App；
- 题型仅支持单选、多选、判断、主观简答四类；
- 单文件 ≤ 20 MB、页数 ≤ 50 页；单次练习出题数 1~50 题；
- 断网时仅提供本地作答暂存，**不在无网络下生成题目或计算诊断报告**。
