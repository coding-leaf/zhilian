# 出题链路反馈与结果可见性

## Goal

让「选考点 → 出题 → 核对题目 → 开始作答」这条链路在每一步都有可见结果。
核心：用户点完「一键智能出题」之后，**必须能在屏幕上看到题目**。

## 现象（2026-09-29 用户实测）

「我还在已有资料解析的资料，试着生题，但是没有反馈，我也不知道题目在哪里」

用户用的是**已经解析就绪**的资料——因此本现象**与解析链路无关**，
不是 `09-29-fix-parse-stuck` 的下游后果。这一点必须先说清：
若把它当成解析未完成来处理，会完全修错地方。

## 根因：**已定案**（代码静态事实，无需运行时复现）

**`isConfigMode` 是一个单向开关，预览区永远不可达。**

`src/subpackages/material/pages/questions/index.vue` 中该标识的全部出现位置：

| 行 | 用法 | 读/写 |
| --- | --- | --- |
| 4 | `{{ isConfigMode ? '智能组卷与出题配置' : '核对生成题目' }}` | 读 |
| 6 | 副标题三元表达式 | 读 |
| 12 | `<view v-if="isConfigMode" class="config-section">` | 读 |
| 134 | `<button class="reconfig-btn" @tap="isConfigMode = true">重新调整</button>` | **写 `true`** |
| 163 | `const isConfigMode = ref<boolean>(true)` | 初始化 `true` |

**全文件没有任何一处把它写成 `false`。**

后果链条：

1. 用户在配置区勾选考点、题型、题量，点「一键智能出题」。
2. `useQuestionCompose.ts:121-144` 的 `generate()` **真的执行成功**：
   请求发出、LLM 返回、`questions.value = generated`、`hasGenerated.value = true`。
3. 但页面的 `isConfigMode` 仍是 `true` → 渲染的仍是配置区，
   **104 行的 `v-else` 预览区（`preview-section`）连同它内部的**
   **`QuestionPreviewCard` 列表、覆盖缺口提示、「开始作答」按钮全部不渲染。**
4. `generate()` 成功路径**没有任何 toast**（失败路径有，见 `:133`/`:140`）。
   于是：按钮转一下就恢复，屏幕**一个像素都没变**。

这正是「没有反馈，我也不知道题目在哪里」——题目确实生成了，只是被一片永远为真的 `v-if` 挡在屏幕外。

### 同一根因带出的次生缺陷（都必须一起修）

| # | 缺陷 | 说明 |
| --- | --- | --- |
| D1 | 预览区不可达 | 上面的主因 |
| D2 | 生成成功无反馈 | 成功路径无 toast、无 notice。`generationNotice` 是 computed，但只在预览区渲染 → 同样被挡住 |
| D3 | 「题目在哪里」无处可答 | 即使修好 D1，用户在**讲义详情页 / 工作台**也找不到「我之前生成过哪些题」。题目只活在 `useQuestionCompose` 的内存 ref 里，页面一退就没了 |
| D4 | 覆盖缺口提示不可见 | `coverage.missing` 的缺口提示块（`:109-116`）与「补齐缺失考点」按钮同样在死区 |

## Change Boundary

### In scope

- **R1 修好状态开关**：生成成功后进入预览态，使预览区可达。
- **R2 补齐生成反馈**：成功路径给出可见反馈（成功 notice / toast），
  并把 `generationNotice` 的题量调整说明**在进入预览态后仍然可见**。
- **R3 结果可回访**：让用户退出页面后仍能找到已生成的题目（见下「R3 的最低成本选择」）。
- **R4 死区自查**：把本页所有 `v-if` 分支过一遍，确认没有第二个「只读不可达」的分支。

### R3 的最低成本选择（先做这个，不扩成新功能）

用户问的是「题目在哪里」。有两种解法：

| 方案 | 成本 | 取舍 |
| --- | --- | --- |
| **A（选它）**：生成成功后**把题目 id 固化到本次练习的入口**，并在讲义详情页给出「上次生成 N 题，继续核对」的入口 | 小，复用已有 `GET /questions?material_id=` 与既有列表渲染 | 不引入新概念，符合「本次只修反馈」的边界 |
| B：新建「我的题库」页面 | 大，需新的信息架构与导航 | 属新功能，超出本次修复范围 |

**A 的依据**：`materialStore.loadQuestions(materialId)` 与 `apiGetQuestionsByMaterial` **已经存在**
（`stores/material.ts:139-142`），后端也已持久化题目（时间成本低）。
本任务只负责**把这个已有能力接到用户看得见的地方**，不新建能力。

### Out of scope（明确不做）

- **不做「我的题库」独立页面**（见 R3 方案 B）。
- **不改 `useQuestionCompose` 的组卷算法**（分批、覆盖率核算、`MAX_QUESTION_BATCH` 全部保持原样）。
  本次它是**正常工作的**——`generate()` 成功执行即为证。
- **不改考点为空时的提示**（`:32-36` 已有「当前范围暂无已解析考点，请先完成资料解析。」，
  这条提示是对的，是解析链路的正确下游表现）。
- **不改 `PracticeEntryCard` / 报告页**——它们不在本页链路上。

## Requirements

### R1 — 预览区可达

- 生成成功后进入预览态。状态迁移必须**显式且单向可回**（「重新调整」回配置态后，
  已生成的 `questions` 与 `selectedKpIds` **不得丢失**，否则用户重新调整等于从头再来）。
- 生成**失败**或**零合格题**时**不得**进入预览态（否则会展示一个空列表，比留在配置区更糟）。

### R2 — 反馈可见

- 成功：给出成功提示，且提示中带上**实际生成题量**（用户真正想知道的是「生成了几道」）。
- 题量被调整（`plannedCount > questionCount`）时，调整说明在预览态中可见。
- 覆盖缺口存在时，缺口提示与「补齐缺失考点」按钮可见（`v-if="coverage.missing.length > 0"` 已在正确位置，
  修好 R1 后自然可达——但要**验证**它真的显示了）。

### R3 — 结果可回访

- 讲义详情页（`subpackages/material/pages/course/index.vue`）提供「继续核对已生成题目」入口，
  条件是 `apiGetQuestionsByMaterial` 返回非空。**空则不渲染该入口**（不造空态）。
- 入口跳转携带足够的上下文，使用户回到 `questions/index.vue` 时能直接看到题目
  （即 R1 修好后需要有「带着已有题目直接进预览态」的路径）。

### R4 — 死区自查

- 逐个核对本页所有条件渲染分支，确认每个分支都存在把它置为真的写点。
- 把该方法（怎么系统性地发现「只读不可达分支」）沉淀为一条可复用的检查手段，
  并以 spec 更新形式留档（走 `trellis-update-spec`，不在本任务里临时发明规范）。
