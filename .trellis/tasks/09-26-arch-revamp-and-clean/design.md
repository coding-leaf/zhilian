# Technical Design: 架构全面重构与代码肃清优化 (design.md)

## 1. 架构目标与重构原则
本次重构的核心哲学是：**“结构清澈、高内聚低耦合、性能优先、体验丝滑、零业务破坏”**。
- **不变性原则**: 不改变任何对外暴露的 RESTful 接口契约，不改变数据库底层持久化 schema，确保已有客户端与数据资产无缝兼容。
- **增量可验证**: 每一个优化小步必须在全量单元测试与类型门禁的守护下推进。

## 2. 核心架构设计与重构方案

### 2.1 依赖与工程结构清理
- 梳理根目录与各子模块目录，核实并不再保留临时中间产物。
- 检查 `backend/pyproject.toml` 与 `miniprogram/package.json` 中的依赖项，确保仅引入生产与开发必需包。

### 2.2 资料解析与高耗时流程退避机制 (Polling Optimization)
- **当前现状**: 前端 `useMaterialPolling` 采用固定频率定时轮询，对服务单例产生高频重复请求。
- **优化方案**: 升级为带抖动的指数衰减轮询策略 (Adaptive Exponential Backoff):
  - 初始间隔 1.5s -> 2.5s -> 4s -> 6s (上限 8s)。
  - 若处于完成态 (READY) 或失败态 (FAILED) 即刻停帧。
  - 增加最大轮询超时安全熔断（例如 3 分钟），超时自动转为提示用户并解除挂起。

### 2.3 领域服务与持久层流水线收敛
- **后端 Material / Knowledge / Question 流水线优化**:
  - 优化向量检索（Hybrid Search Adapter）中的 Top-K 粗排与 RRF 融合打分执行效率，杜绝重复从数据库读取完整切片正文。
  - 统一领域层异常派发逻辑，精简冗余的日志格式化和多级包装。

### 2.4 前端体验与组件状态机优化
- 抽离重复的全局通用 UI 状态提示。
- 规范 Pinia Store 中的 Action 调度，保证同一资料/题目列表操作的局部响应式变更最小化，减少 UniApp 页面全量 re-render 损耗。

## 3. 风险控制与回滚机制
- 依托现有 1087 项后端单元测试 + 415 项前端单元测试作为强力安全网。
- 架构分层守卫：`lint-imports` 强制拦截任何跨层污染（Repository 不得触碰上层，Integrations 不得触碰业务层）。
