# 全项目 Bug 自查与功能性修复

## Goal

对 `zhilian` 全项目（前端 `miniprogram/` uni-app + Vue3 + Pinia；后端 `backend/` FastAPI 分层架构）做一次只读 bug 审计，并在此基础之上修复全部功能性缺陷至清零。非功能性发现（重复造轮子、死代码、坏味道、规范违背）仅记录，不混修，重构/去重另开独立任务。

## Requirements

### 需求来源
- 用户诉求：全面自查前后端 bug（组件逻辑错误、渲染问题、后端逻辑问题、重复造轮子等），"一切为了功能进行修复"。

### 功能要求
1. **审计**：产出前后端统一的分级 bug 总清单，每条附证据（工具链命令/静态位置 `file:line`）。
2. **修复**：功能性 bug 按 **P0/P1/P2 全级别修到清零**。
3. **重构隔离**：重复造轮子/死代码/坏味道只记录，作为独立重构任务另议，不与功能性修复混合提交。

### 约束（核心决策）
| 维度 | 决策 |
|---|---|
| 推进方式 | 只读审计先行 → 用户确认清单 → 分批修复 |
| 证据标准 | 工具链实测 + 静态审阅（双证据） |
| 切片粒度 | 垂直功能切片：认证 → 素材/知识点 → 题目生成 → 练习 → 评分 → 报告/诊断（前后端同片查） |
| 非功能性发现 | 记录不混修，重构另开任务 |
| 修复切割线 | 功能性 bug 全级别(P0/P1/P2)清零 |
| 验收门禁 | 每切片：回归测试（先红后绿）+ 全工具链绿 |
| 任务树 | 父 + 1 审计子（清单）+ 确认后按切片建修复子 |
| P2 边界 | 仅客观可判定项（空指针/越界、未处理异常与 Promise 挂起、类型漏洞、契约不一致、状态未重置） |
| 前端渲染 | 组件测试 + 静态为证据；真机/开发者工具专属问题标"疑似待人工验证" |

### 不在范围内（Non-Goals）
- 主观 UX 偏好（文案/交互/布局品味）的分级与修复。
- 微信开发者工具/真机渲染的物理实测。
- 重复造轮子/死代码的重构落地（仅记录）。
- 依赖真实 Postgres/Redis/LLM 的基础设施联调（集成测试用 in-memory fake 覆盖）。

## Acceptance Criteria

- [ ] 父任务下挂：1 个"全量只读审计"子任务 + 按垂直切片拆分的修复子任务。
- [ ] 审计子任务产出统一分级（P0/P1/P2）bug 总清单，每条含证据与 `file:line`，落盘到任务 `research/`（或清单制品）。
- [ ] 用户对清单给予确认后，才按切片创建并启动修复子任务。
- [ ] 每个修复子任务：相关回归测试先红后绿 + 全工具链绿（后端 `uv run` 门禁；前端 `pnpm` 门禁）。
- [ ] 功能性 bug P0/P1/P2 全部清零（对照清单逐条关闭）。
- [ ] 非功能性发现单独成册，不进入本轮代码提交。
- [ ] 最终整体回归：后端与前端全量工具链通过。

## Notes

- 本任务为父任务，承载需求集、任务地图与跨子任务验收标准；具体交付在子任务内完成。
- 子任务依赖关系写在各自 `prd.md` / `implement.md`，不依赖树位置隐式表达。
