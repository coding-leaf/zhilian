# 学习闭环修复执行清单

开始前：复查工作区未提交变更及最新 `prd.md`/`design.md`，按 `trellis-before-dev` 加载 backend、frontend 和跨层规范；只有用户批准最终规划总结后才执行 `task.py start`。以现有业务提交为基线记录测试结果，避免覆盖他人改动。

## 顺序

- [ ] 1. 固定后端响应样本和契约表：资料状态、题目、练习、诊断、错题、题目助教；先为缺陷写失败测试。
- [ ] 2. 后端资料上传关闭双重自动调度，增加 `not_started`，保留手动解析/失败重试；补数据库及接口兼容测试。
- [ ] 3. 接入 RQ Redis adapter、受控任务注册与独立 worker 启动/部署配置；解析与判题任务处理幂等、有限重试、终态回写、滞留排查。使用真实 Redis 测一次跨进程消费。
- [ ] 4. 修正判题完成与诊断门禁，补结果页所需状态/字段、自评及复查接口测试；堵住提交后立即生成报告的竞态。
- [ ] 5. 头像对象上传与持久化、课程归属错题分组/筛选、按范围再生题后端契约；补权限、分页、上传失败和旧数据测试。
- [ ] 6. 课程助教按授权范围检索切片，新增 LangGraph 证据门控/引用校验/一次修复或拒答；测试无证据、越权、坏引用、LLM 失败。复用现有结构化输出图。
- [ ] 7. 前端统一 API adapter、配置化 host/登录失效、头像/课程 UI、资料状态与手动解析；对齐后端响应模型 fixture。
- [ ] 8. 前端出题核对、覆盖校验、七题型练习、草稿保存顺序、提交幂等、结果与诊断分阶段展示、错题巩固、助教来源展示；测试慢网、失败、跨页恢复。
- [ ] 9. 微信端到端走上传 -> 解析 -> 出题核对 -> 作答 -> 判题 -> 诊断 -> 复查 -> 错题再生，并覆盖中途退出；修复本任务内发现的既有 Ruff 门禁问题。
- [ ] 10. 执行完整 `task verify`，核对后端 schema 和前端 adapter 字段、状态机及部署 worker 配置；更新误称已闭环的前端 spec，记录测试证据与外部服务限制。

## 重点回滚点

- 数据迁移：`ParseStatus` 新值与头像对象键；旧状态/URL 必须仍可读。
- 队列切换：旧 Redis List 与新 RQ 队列不互通，上线前盘点积压与悬挂业务状态；可在流量切换前回滚生产 adapter 配置，不可把旧任务当作已消费。
- 诊断门禁：后端先发布以禁止早产报告，再发布前端结果页；前端需兼容旧响应缺少新增分组字段的过渡期。
- 工作区现有大量未提交变更，逐文件审阅后再编辑，不用重置/清理命令。

## 验证命令

`task verify` 是完成门禁；可按层先跑 `task verify-backend` 与 `task verify-frontend`。Redis/对象存储/微信端到端需额外记录实际环境和结果，不能用纯 mock 测试冒充。修复完成后用 `trellis-check` 做跨层一致性检查。
