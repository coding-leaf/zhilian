# PRD: 架构全面重构与代码肃清优化 (arch-revamp-and-clean)

## 1. 目标与用户价值 (Goal & Value)
本项目经历多轮快速迭代演进，存在部分历史冗余文件、重复抽象及未充分发挥性能的旧范式。
为了给后续功能扩展打下坚实地基，全面提升系统响应速度与端到端交互体验，本任务的目标是：
1. **肃清无用资产与死代码**：系统化清理工程中已失效的配置、孤立组件与未引用的临时文件。
2. **规范领域架构范式**：收敛与统一数据层操作、错误处理及依赖注入规范，减少冗余样板代码。
3. **性能提速与响应优化**：
   - 后端优化关键链路（资料分块处理、向量混合检索与题目流式生成）吞吐与并发表现；
   - 前端精简打包体积，优化组件状态流转与轮询机制，提升页面秒开与交互流畅度。

## 2. 事实与基线现状 (Facts & Evidence)
- **后端基线**:
  - Python 3.12 + FastAPI + SQLAlchemy 2.0 + LangGraph + pgvector。
  - 拥有 1087 项单元与集成测试，覆盖率 >94%，5 条 import-linter 分层规则全绿。
- **前端基线**:
  - UniApp (Vue 3 + Vite + TypeScript + Pinia + UnoCSS/SCSS)。
  - 拥有 415 项单元测试，ESLint / Vue-tsc 全通过。
- **现存痛点**:
  - 部分旧文档/模板及废弃调试文件散落；
  - 部分领域服务中存在重复的仓储查询与状态组装逻辑；
  - 前端资料长轮询缺乏自适应指数退避，消耗不必要的网络与计算资源；
  - 大模型交互场景仍存在部分阻塞等待，缺乏精细的并发与状态缓存。

## 3. 功能需求与重构范围 (Requirements)

### R1. 全工程无用文件与废弃资产肃清 (Dead Code & Asset Clean-up)
- **R1.1 根目录与配置精简**: 清理历史遗留的无用脚本、废弃的 CI/开发临时文件。
- **R1.2 依赖清点与死代码剔除**: 检查 `backend` 与 `miniprogram` 的未引用依赖与未使用的导出接口/组件，保持依赖树最小化。

### R2. 统一领域范式与架构精炼 (Domain & Architecture Refactoring)
- **R2.1 后端统一错误响应与领域异常矩阵**: 规范异常捕获与日志脱敏，消除各服务重复的 try-except 模板代码。
- **R2.2 仓储与服务层解耦精简**: 消除重复查询与 N+1 潜在风险，规范事务提交流程。
- **R2.3 前端 Store 与数据流收敛**: 规范 Pinia 状态管理模式，清除组件内部冗余的重复状态副本。

### R3. 性能优化与交互体验提速 (Performance & UX Optimization)
- **R3.1 前端长轮询自适应退避**: 将资料解析等轮询机制升级为自适应衰减轮询（从 1s -> 2s -> 5s 动态调整，并增加最大轮询超时自愈保护）。
- **R3.2 后端高频查询与向量检索加速**: 优化 pgvector 向量索引与关联查询加载策略，减少不必要的全字段序列化。
- **R3.3 前端打包与静态资源加载优化**: 消除未使用的样式规则，优化分包体积。

## 4. 验收标准 (Acceptance Criteria)
- **AC1 (无用文件肃清)**: 根目录与模块结构完全清晰干净，无任何失效旧脚本或死代码。
- **AC2 (代码门禁零破坏)**: 现存所有核心业务逻辑行为不变，后端 1087+ 测试与前端 415+ 测试 100% 保持通过。
- **AC3 (架构分层合规)**: `uv run lint-imports` 架构契约 100% 遵守，零分层违背。
- **AC4 (类型与静态检查)**: Mypy、Ruff、ESLint、Vue-tsc 零错误、零警告。
- **AC5 (性能指标提升)**: 轮询网络请求频率合理衰减，前后端无阻塞性能隐患。

## 5. 非范围项 (Out of Scope)
- 不破坏已有对外 API 契约（保持向后兼容，不改变端点路径与请求报文结构）。
- 不破坏数据库已有生产表结构（不做不可逆数据库清空或字段删除）。
