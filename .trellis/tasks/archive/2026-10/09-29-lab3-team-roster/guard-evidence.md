## 机制

| 文件 | 作用 | 是否被 git 跟踪 |
| --- | --- | --- |
| `.git/hooks/zhilian-name-guard.sh` | 共享字面量与判定逻辑 | 否（`.git/` 不入库） |
| `.git/hooks/pre-commit` | 扫描**暂存内容**（index） | 否 |
| `.git/hooks/commit-msg` | 扫描**提交信息** | 否 |

字面量只存在于 `.git/hooks/` 内。这是该方案优于「仓库内检查脚本」的原因：后者会把真名本身提交上去。

## 残留核验

`git add` 会把含真名的内容写成 blob 存进本地对象库，故取证后必须清除：

```
git reset HEAD <test-file>
git reflog expire --expire-unreachable=now --all
git prune
```

清除后做**全对象库流式扫描**（单进程 `git cat-file --batch-all-objects --batch` 管道给 grep）：

```
git cat-file --batch-all-objects --batch | grep -a -c -E '<四个真名>'
→ 0
```

**结论：对象库中不存在含真实姓名的任何对象。** 不可达对象另有 188 个（历史遗留的
tree/blob），经同一扫描确认均不含真名。
