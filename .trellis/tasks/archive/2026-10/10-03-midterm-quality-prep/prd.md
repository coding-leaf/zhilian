# 中期质量检查：准备与计划

## Goal

把期中质量检查的**第 1 步「准备与计划」**做成可直接执行的成品：四份产出
（《中期质量计划》《评审清单》《单测计划》《排期表》）落进公开仓库 `中期质量检查/`，
外加四份可复用模板。老师点开即可看懂「查什么、按什么标准查、谁查、什么时候查完」，
不需要口头补充。

用户价值：把"质量检查"从一次性抽检变成有范围、有标准、有角色、有排期的工程动作；
且四份文档中的每一条都能在仓库里定位出处（文件路径 / 实跑命令 / 提交号），不是口号。

## 需求源（用户原文，保留）

> 根据 trellis 流程，第 1 步：准备与计划
> 目标：明确中期质量检查的范围、标准、角色和排期。
> 主要工作：
> - 确定评审范围：优先覆盖新增代码、修改频繁模块、核心业务、高风险模块。
> - 制定准出标准，例如：单元测试通过率 100%；新增代码覆盖率 ≥ 70%~80%，核心模块 ≥ 90%；
>   静态扫描无阻塞问题；代码评审问题全部闭环。
> - 明确角色：开发、测试、评审人、记录员、项目/QA 负责人。
> - 准备模板：单元测试用例模板、PR/MR 模板、评审检查清单、缺陷记录表。
> 输出：中期质量计划、评审清单、单测计划、排期表。

## 硬约束

- **C-1 仓库零真名**：仓库公开（`github.com/coding-leaf/zhilian`）。四份产出进 `master`，
  一律使用 lab3 既有的四个角色代号（TechLead / SecLead / Reviewer / DevOpsLead），
  不出现任何真实姓名。
- **C-2 不新造角色**：角色与所有权沿用 `docs/团队分工.md`（其事实源是
  《代码管理工作介绍 V1.0》），不另立一套岗位。
- **C-3 不污染门禁**：本任务只产出文档与模板，**不改业务代码、不改 `Taskfile.yml` 的门禁命令**。
  门禁口径的变更（如新增增量覆盖率）只写进《单测计划》作为待办，由后续任务实施。
- **C-4 不覆盖既有文档**：新增内容与 `docs/开发过程文档.md`、`docs/后续待解决问题.md`、
  `docs/团队分工.md` **互相引用、不重复、不改写**。
- **C-5 数字不手抄**：文档中的测试规模、覆盖率等易变数字，必须附**取得它的命令**，
  且标注采集日期；不得直接抄自另一份文档（已发现三份文档数字互不一致，见 research）。

## 需求

### R1 中期质量计划（`中期质量检查/中期质量计划.md`）

- R1.1 写明检查目标、范围边界、**不在范围内**的事项。
- R1.2 给出**现状基线表**：代码规模、测试规模、门禁现状，每个数字附取得命令与采集日期。
- R1.3 定义**准出标准**，分「硬门禁 / 增量门禁 / 人工评审」三层，逐条可判定：
  - 单测通过率 100%（含墙钟抖动的取证与排除规则）；
  - 增量覆盖率：新增/改动代码 ≥ 80%，T0 核心模块 ≥ 90%（前端须先接入覆盖率工具）；
  - 静态扫描无阻塞问题（ruff / mypy / import-linter / eslint / vue-tsc + 安全扫描）；
  - 代码评审问题全部闭环（缺陷台账无 open，或已显式决策顺延并留痕）。
- R1.4 给出**角色与 RACI**：把「开发 / 测试 / 评审人 / 记录员 / 项目与 QA 负责人」
  映射到四个代号，一人多角，且与 `docs/团队分工.md` 的所有权矩阵一致。
- R1.5 列出检查**流程与里程碑**（引用《排期表》），并写明每个里程碑的准出判据。
- R1.6 列出**工具与取证方式**（每条标准对应的可执行命令）。
- R1.7 列出**风险与已知偏差**（墙钟抖动、覆盖率排除清单、无组件测试、文档数字漂移等）。

### R2 评审清单（`中期质量检查/评审清单.md`）

- R2.1 按风险分级（T0/T1/T2）列出**本项目具体模块**，每个模块给"检查项 + 证据要求 + 评审人"。
- R2.2 T0 模块必须逐条覆盖三类编译器盲区：算法核、鉴权与用户隔离、错误契约。
- R2.3 每条检查项必须是**可验证的**（能指向命令、文件或输出），不得写"代码优雅"这类不可判定项。
- R2.4 明确评审**放行/打回**规则，与 `docs/团队分工.md` 的双人评审要求一致。

### R3 单测计划（`中期质量检查/单测计划.md`）

- R3.1 给出覆盖率口径定义与公式（增量口径：改动行命中率），并写明采用的工具与命令。
- R3.2 给出**需补测的模块清单**（依据 T0 分级 + 前端无覆盖率的现状）。
- R3.3 正面处理**墙钟微基准抖动**（E-1）：取证规则、是否排除、如何留痕。
  **不放宽阈值**（遵守 `AGENTS.md` 既有结论）。
- R3.4 规定用例命名、结构、断言要求，并沿用既有**变异验证**纪律。
- R3.5 给出单测的**验收判据**与取证命令。

### R4 排期表（`中期质量检查/排期表.md`）

- R4.1 以**主链路 8 节点**为切片主轴，给出里程碑（M0–M4）与每个里程碑覆盖的节点。
- R4.2 每个里程碑标注：负责人（代号）、依赖、准出判据、可交付证据。
- R4.3 标明与既有未收口任务（P0-1 / P0-2 / P1-3 / P1-4 / P1-5 / 题库 Tab）的衔接关系，
  **不重复立项**。

### R5 模板（`中期质量检查/templates/`）

- R5.1 `单测用例模板.md`；R5.2 `PR-MR模板.md`；R5.3 `评审检查清单模板.md`；R5.4 `缺陷记录表模板.md`。
- R5.5 模板为**空白可复用**版；`评审清单.md` 是按其填好的**本项目实例版**，两者区分清楚。

### R6 目录索引（`中期质量检查/README.md`）

- R6.1 说明四份产出与四份模板的用途、阅读顺序、相互关系，以及它们与既有文档的引用关系。
