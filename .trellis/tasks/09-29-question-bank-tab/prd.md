# 题库 Tab 重构：我的题目与错题

## Goal

把当前「学情」Tab 重新定义为一个**能自解释的「题库」页**：上半是按出题批次分组的题目（支持跨批次选题再练），
下半是错题与举一反三。

用户原话是「学情界面，意义不明？感觉可能要重新设计」。本次**不做修补式改动，而是重新定义这页是干什么的**——
所以本任务持有需求源、任务地图与跨子任务验收标准，同时承担页面骨架与错题区块的直接实现。

**用户价值**：让用户能回答两个问题——「我出过的题在哪」（现在无处可看）、「我做错的题怎么再练」（现在入口埋在
一个他看不懂的页面上）。

## 需求源（2026-09-29 用户口述，原文保留）

1. 「我现在有俩需求 希望一个页面显示为题库，下面是题目批次分类，可以选择不同批次的题库在一起再次答题。**如果太麻烦就算了。**」
2. 「生题不能按批次显示归类」
3. 「最好还能记录手动错题，根据错题再次生题」
4. 「学情界面，意义不明？感觉可能要重新设计」

需求 2 同时登记在父批次 `09-29-field-test-fix-batch-1` 的需求 7；本任务树承接后，**该条目不再由那个批次负责**。

## 用户已确认的决策（2026-09-29，四项）

| 决策点 | 取值 | 影响 |
| --- | --- | --- |
| 立项范围 | 本任务（父）+ 题库区块 + 手动标记错题 | 三个任务，本任务为集成目标 |
| 手动错题的形态 | **标记已有题目**（轻），不是手打外部题目 | 无需录入表单；`question_id` 一定存在 |

| --- | --- | --- |

零数据下的实际呈现：三个数字全为 0、0、0；三个区块各自的空态文案叠在一起，整页没有任何「我该先做什么」。

## 已确认事实（含证据锚点）

### F1｜接口错题记录的 `material_id`/`folder_id` 缺失 —— **已修复，但零测试覆盖**

**这一条在继承自 `09-29-review-page-ia` 时是「确定缺陷」，撰写本 PRD 时核实发现已被修复。
如实记录，避免按过期结论重复施工。**

- **曾经的失效机制**（供理解为何需要防回归测试）：`app/api/v1/diagnosis.py` 曾拿 `WrongRecord`
  ORM 实体直接 `WrongRecordItemResponse.model_validate(r)`，而 `material_id`/`folder_id`
  **不在这张表上**——它们挂在 `Material` 上，要经 `KnowledgePoint` 跳一层；
  schema（`app/schemas/diagnosis.py:403-404`）声明了这两个字段、默认 `None`，当时**没有任何人赋值**。
  于是同一接口内两条路径不一致：`repositories/diagnosis.py:625` 的 `list_wrong_record_groups`
  `outerjoin(MaterialFolder)` 后 `groups` 的归属是**对的**，而 `items` 里每条都是 `None`。
  前端 `src/api/adapters/wrong.ts:85-92` 的 `recordsInGroup` 用**每条记录自己的** `material_id`
  精确匹配 → `null === '24f82195'` 恒假 → 该组可见记录 **0 条**，
  界面同时显示「待攻克错题 8」与「当前范围内没有待巩固的错题」。
- **现状**：`15a621e`（2026-09-29）新增 `DiagnosisRepository.get_wrong_record_scopes`
  （`app/repositories/diagnosis.py:608-624`，一次 `in_()` 查询按知识点批量解析 material/folder），
  并在 `app/api/v1/diagnosis.py:338-350` 对全部 items 批量回填。该提交已在本分支历史中，
  **N+1 与归属缺失两个问题都已消除**。
- **仍未消除的**：`get_wrong_record_scopes` **零测试覆盖**（`grep -rn get_wrong_record_scopes tests/` 无命中）。
  它修掉的失效模式恰好是**接口内部两条路径互相矛盾**——单看任一路径都「正常」，
  没有测试就没有任何东西拦得住它复发。这正是本任务 R2 的真实内容。

`wrong_records` 实际列（供后续设计与 F1 无关的字段核对）：
`id, user_id, question_id, knowledge_point_id, practice_id, attempt_item_id, error_type,
error_count, is_mastered, last_wrong_answer, question_snapshot, first_wrong_at, mastered_at,
created_at, updated_at`。

### F2｜请求错误被吞，空态与故障态不可区分（**确定缺陷，且有两处**）

核实于撰写本 PRD 时（`15a621e` 之后），**仍然成立**：

- `src/pages/review/index.vue:168-170` 的 `loadWrongs` catch 里只有 `console.error('Failed to load wrong records', error)`。
- `src/pages/review/index.vue:178-180` 的 `loadPractices` catch 里只有 `console.error('Failed to load practices', error)`。
  **这一处与上一处是同一个缺陷，规划时容易只修前者。** 两处都必须修。

后果：**「后端返回 0 条」与「请求失败」在界面上完全一样**。这直接违反父批次 XAC-4。

本次排查被它实际卡住过一次：用户报「数字没更新」，无法从界面区分是缓存、是请求失败、还是真的没数据。

### F3｜「数字没更新」已澄清为缓存（**不是缺陷，别再去修**）

该页只在 `onMounted`（`pages/review/index.vue:184-186`）与 `onPullDownRefresh`（`:188-191`）加载，
没有定时刷新、也没有 `onShow` 重载。下拉后数字即正确。**这是设计选择不是 bug**——
重构时可以决定是否改为 `onShow` 重载，但**不要以「修复缺陷」的名义改它**。

### F4｜`batch_id` 是无可读含义的随机码

`app/services/question.py:790` / `:1121` / `:1254`：`batch_id = f"batch_{uuid.uuid4().hex[:12]}"`。
**没有时间戳、没有来源信息、没有序号**。所以界面上任何「批次」标签都必须**推导**出来
（创建时间 + 来源资料/课程 + 题量），不能直接显示 ID。

### F5｜跨批次再练不需要 LLM

`practiceStore.regenerateFromWrongPoints`（`src/stores/practice.ts:200-208`）要调 LLM 生成新题，
所以它硬校验「范围必须且只能是单一课程或单一未分类资料」。这**不适用于**本任务：
跨批次再练是 `POST /practices` 直接传 `question_ids`，零 LLM 成本、零范围限制。
**这是需求 1 成本低但需求 3 的再生题成本高的根本原因，规划时不得把两者混为一谈。**

> ⚠️ **但「零 LLM 成本」不等于「传了就全练」**：显式题目路径仍按 `question_count`
> 切片（默认 10）。调用方必须显式传 `question_count = 计划题数`。
> 详见 `09-29-question-bank-page` 的 PRD F3 更正块与设计决策 4 的更正块——
> 那里记录了这条契约最初被误判为「不截断」的全过程。

### F6｜「举一反三」的覆盖率声明不可信（**既有缺陷，在 A 的 check 阶段查实**）

`src/stores/practice.ts:231-239`：

```ts
const coverage = computeKnowledgeCoverage(generated, knowledgePointIds)   // ← 按「全部生成题目」算
const session = await apiCreatePractice({
  title: '错题巩固练习',
  question_ids: generated.map((question) => question.id),                 // ← 没传 question_count
  source_type: 'wrong_record',
})
```

而后端显式题目路径的语义是**「候选题目 + 目标题数」而不是「就练这些」**：
`app/services/practice.py:473` 执行 `ordered_explicit[: options.question_count]`，
`question_count` 默认 **10**（`app/schemas/practice.py:70-75`，`ge=1, le=50`）。

**后果**：用户有 >10 个错题知识点时，生成 20 道题覆盖 20 个考点，练习里只装前 10 道，
而 `coverage` 按全部 20 道算 → 界面**声称某些考点已覆盖，而对应题目根本没进练习**。
`generated` 与「实际进入练习的题目」是两个集合，覆盖率却只声明前者。

**为什么归本任务**：错题区块与举一反三入口是本任务的范围，而这段代码就在那条链路上。
**它还连带卡住** `09-29-manual-wrong-mark` 的 AC-6（见该任务 PRD F8）——
在修好之前，B 无法端到端地证明「手工错题被练到了」。

**同一根因的另一个受害面**：`POST /practices` 的 `question_count` 默认值是
**所有显式 `question_ids` 调用方**的陷阱，不止这一处。修的时候要通盘看，
不要只给举一反三打一个补丁。

## 本任务自身的需求

### R1 — 页面重新定义（不是重排）

- 页面从「学情概览」改为「我的题目与错题」，**上半是题库（子任务负责），下半是错题与举一反三**。
- **tabBar 文案由「学情」改为「题库」**（`src/pages.json:34-52`）。依据：用户说「学情」意义不明，
  而他为自己要的东西选的名字是「题库」。这是本次唯一的命名改动，若用户否掉则保持「学情」。
- **删除 summary 卡**（含「归属范围」这一格）。「待攻克错题 N」并入错题区块标题，不再单占一屏。
  - 「归属范围」的处置结论：**删除**。它当前是 `groupOptions.length`（错题涉及多少个课程/资料范围），
    对用户而言 `0` 既可能是「没有错题」也可能是「错题还没归属课程」——两种完全不同的处境共用一个数字，
    且 F1 修好前它连算都算不准。父任务 AC-5 要求它不留悬空，这里给出结论。

### R2 — 为 F1 补防回归测试（**不是重新实现**）

- F1 的修复（`get_wrong_record_scopes` + 批量回填）**已经存在，不要重写**。
- 本需求只做一件事：把那对**互相矛盾的两条路径**变成会失败的测试——
  同一接口响应中，每条 `items` 的 `material_id`/`folder_id` 必须与其 `groups` 分组的归属一致。
- 测试必须能在那段回填被删除/改坏时失败。**断言「items 非空」是不够的**——
  缺陷期的 items 也是 8 条，只是字段全 `None`。

### R3 — 修 F2（错误可见，两处）

- `loadWrongs` 与 `loadPractices` **两处**的加载失败都必须给出用户可见反馈，
  且与「真的没有数据」在文案与视觉上不同。
- 失败态必须带可重试动作。

### R4 — 零数据与首次进入的自解释

- 用户还没出过题、也没做过练习时，页面必须能说明「这页是干什么的 + 我该先做什么」，
  而不是叠三句「太棒了！没有错题」这样的**伪正向**文案。
- 「没有错题」与「还没开始过」必须是两种不同的呈现。

### R5 — 保留「我的练习」

- 它是续答未完成练习与打开历史报告的**唯一入口**，不得删除。
- 位置：放在错题区块之后（零练习时它不该占据第一屏，这正是当前版本的毛病之一）。

### R6 — 修 F6：举一反三的题量与覆盖率必须一致

- 「举一反三」创建的练习，其**实际题数**必须等于覆盖率所依据的题目集合大小。
- 具体：`regenerateFromWrongPoints`（`src/stores/practice.ts:231-239`）必须显式传
  `question_count`，或者把 `computeKnowledgeCoverage` 改为按**实际进入练习的题目**计算。
  **二者选一，由实现时权衡**——但要写清选了哪个以及为什么。
- 建议一并检查 `POST /practices` 的**其它** `question_ids` 调用方是否有同样的默认值陷阱。
- **不得**只给举一反三打一个补丁而不看同一根因的其它调用点。



## Out of Scope

- **不动 `09-29-fix-learning-stats` 的个人页统计**——那是「我的」Tab，不同页不同职责。
- **不引入新的学习指标**（掌握度趋势、学习时长、连续打卡等）：那是产品新增，不是本页重构。
- **不改判题、组卷、解析链路**：本任务只消费它们产出的数据。R6 只改**调用方的参数传递**，
  不修改 `PracticeService` 的组卷语义。
- **不新增学习的 Tab**：已确认并入本 Tab（tabBar 由「学情」改名为「题库」）。
- **手打外部错题**（录入题干/答案的表单）：用户已明确选「标记已有题目」，不做。
