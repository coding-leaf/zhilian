# 题库 Tab 重构：技术设计

## 核心设计决策

### 决策 1｜页面骨架：三段式，删掉 summary 卡

**目标结构**（自上而下）：

| 顺序 | 区块 | 归属 | 数据源 |
| --- | --- | --- | --- |
| 1 | **我的题目**（按批次分组 + 跨批次再练） | 子任务 `09-29-question-bank-page` | 新接口 `GET /questions/batches` |
| 2 | **错题巩固与错题列表** | 本任务 | `apiListWrongRecords` |
| 3 | **我的练习** | 本任务 | `practiceStore.loadPractices` |

**删除 summary 卡**（现 `pages/review/index.vue:3-22`）。理由：

- 「归属范围」这一格**没有可定义的语义**——它是 `groupOptions.length`（错题涉及多少个课程/资料范围），
  对用户而言 `0` 既可能是「没有错题」也可能是「错题还没归属课程」。两种完全不同的处境共用一个数字。
  父任务 AC-5 要求给出处置结论：**删除**。
- 「待攻克错题 N」与「已消灭错题 M」是**错题区块的两个计数**，把它们搬到错题区块标题上，
  信息不丢，却少占了一屏。
- 零数据时整张卡是 `0 / 0 / 0`，是「第一屏什么都没有」的主要来源。

**为什么不保留一张精简卡**：三个数字里有一个要删、另两个有更合适的归属地，
留下空壳卡只是为了保留布局，没有信息价值。

### 决策 2｜先做组件抽取，以守住 ≤300 行硬约定

`docs/DESIGN.md` §6 规定单 `.vue` 文件 ≤300 行（`spec/frontend/index.md` 记为**硬性约定**，
并已列出 5 个既有超标文件）。`pages/review/index.vue` 当前 **252 行**——
挂上题库区块、改骨架、加三态空态之后**必然越界**。

**选择**：把「错题巩固 + 错题列表」抽成 `src/pages/review/components/WrongSection.vue`，
页面只保留骨架与区块编排。

- 目标：`pages/review/index.vue` ≤300 行，新增/改动的每个组件也 ≤300 行。
- 抽取是**纯搬家**，不改行为；先抽、跑一遍既有用例确认零回归，再做骨架改动——
  两步分开提交，出问题时能立刻定位是哪一步引入的。

### 决策 3｜tabBar 与页面标题改名「学情」→「题库」

`src/pages.json:34-52` 的 tabBar `text` 与 `:14-19` 的 `navigationBarTitleText` 同改。

**依据**：用户说「学情」意义不明，而他为自己要的东西选的名字是「题库」。
一个用户看不懂的标签，改名是成本最低、收益最直接的修复。

**这是本次唯一的命名改动，若用户否掉则保持「学情」**（PRD AC-2 要求二者取其一，不留混称）。
改名时必须同步三处：tabBar `text`、页面 `navigationBarTitleText`、页面内部标题文案——
漏改任一处就会出现「标签写题库、标题写学情」的混称。

### 决策 4｜修 F2：两处吞错误，用同一种模式修

**现状**（核实于撰写 PRD 时，`15a621e` 之后仍成立）：

- `pages/review/index.vue:168-170` 的 `loadWrongs` catch 只有 `console.error`。
- `pages/review/index.vue:178-180` 的 `loadPractices` catch 只有 `console.error`。

**选择**：两处都改为「store 失败态 + 页面可见反馈 + 重试动作」，且**与空态使用不同的文案与视觉**。

**具体形态**：每个区块（错题、我的练习、题库）各自持有 `loadError`，
失败时该区块渲染失败态卡片（说明「没拉到数据」+ 重试按钮），
**而不是渲染成空态**。`console.error` 保留（排查用），但它不再**是唯一的**反馈。

**分类复用既有叶子模块**：`src/utils/requestError.ts` 的 `RequestError` / `RequestErrorKind`
（`spec/frontend/state-management.md` 明示这是可被 store/composable import 的错误契约）。
不按 `error.message` 字符串判断类型。

**为什么这条被单列成需求而不是顺手修**：它让「后端返回 0 条」与「请求失败」在界面上**完全一样**。
本次排查已被它实际卡住过一次——用户报「数字没更新」时，无法从界面区分是缓存、是请求失败、
还是真的没数据，最后靠用户手动下拉刷新才确认是缓存。**它是归因工具，不是观感问题。**

### 决策 5｜空态分三档，消除「伪正向」文案

现状零数据下三个区块各自的空态叠在一起，其中「太棒了！当前范围内没有待巩固的错题。」
是**伪正向**——用户根本没做成过任何一次练习，「没有错题」与「还没开始」在体验上必须分开。

**选择**：按「有没有任何活动」分流，判据取自三个数据源：

```ts
// 任一为真即「有活动」；三者皆空才是全新用户
hasActivity = practices.length > 0 || wrongRecords.length > 0 || batchTotal > 0
```

| 处境 | 判据 | 呈现 |
| --- | --- | --- |
| 全新用户 | `!hasActivity` **且无加载失败** | 说明这页是什么 + 题目从哪来 + 「去工作台导入资料」的入口。**不出现任何「太棒了」** |
| 有活动、无错题 | `hasActivity && wrongRecords.length === 0` | 可以说正向，但必须**点明依据**（「做过 N 次练习，还没有错题」） |
| 加载失败 | 任一 `loadError` 非空 | 失败态（决策 4），**不得与上面两档同形** |

**三档互斥且穷尽**，所以不存在「既像空态又像失败态」的缝隙——
这正是父任务 XAC-3 要求的「空态与故障态可区分」。

**注意 `!hasActivity` 必须建立在「加载成功」之上**：若三个请求全失败，
`length` 也都是 0，会把故障伪装成「全新用户」。所以判据是
`!hasActivity && !loadError`，失败优先级高于空态。**这一条是最容易写错的地方。**

### 决策 6｜F1 的防回归测试落在这里（后端代码已存在，不重写）

F1（错题记录 `material_id`/`folder_id` 缺失）在 `15a621e` 已修：
`DiagnosisRepository.get_wrong_record_scopes`（`app/repositories/diagnosis.py:608-624`）
一次 `in_()` 查询批量解析，`app/api/v1/diagnosis.py:338-350` 对全部 items 回填。
**代码不要动。**

**缺口是零测试覆盖**（全仓 `grep -rn get_wrong_record_scopes tests/` 无命中）。
它修掉的失效模式是**接口内部两条路径互相矛盾**——`groups` 说
「material=X, count=8」而 `items` 里每条 `material_id=None`，单看任一路径都「正常」。
没有测试，就没有任何东西拦得住它复发。

**测试要求**：断言 `items` 每条与 `groups` 的归属**一致**。
**断言「items 非空」是不够的**——缺陷期的 items 也是 8 条，只是字段全 `None`。
必须做变异验证：移除回填代码后该测试必须失败（AC-3）。

### 决策 7｜跨子任务的挂载契约

本任务作为父任务，需要给两个子任务留出**明确的接口位**，否则三份实现会在同一页面上互相踩：

| 对方 | 本任务提供 | 对方提供 |
| --- | --- | --- |
| `09-29-question-bank-page` | 页面上部一个区块挂载点（`<QuestionBankSection />` 的位置与容器样式） | 该组件本身及其数据加载 |
| `09-29-manual-wrong-mark` | 无（它的入口在题库区块的题目行内） | 题目行的动作实现；本任务不预留样式，避免与题库区块的组件设计打架 |

**区块各自持有加载态与失败态**：三个区块的三个数据源互相独立，
不能让一个失败把整页渲染成失败态——那会把「我的练习拉取失败」变成「整页打不开」。
**区块级失败隔离**是决策 4 与决策 5 共同的前提。

## 兼容性与回滚

- **前端纯改动，无接口契约变更**。唯一后端改动是**新增一个测试文件**（决策 6）。
- **回滚**：撤掉骨架改动与组件抽取即可恢复原页面；`get_wrong_record_scopes` 不动，
  所以回滚**不影响**已修复的 F1。
- **`groupOptions` 的删除面**（AC-6）需要清干净：
  `pages/review/index.vue` 的 `groupOptions.length` 引用、`summary-card` / `stats-row` /
  `stat-col` / `stat-divider` 相关样式，以及 `src/api/adapters/wrong.ts` 里**仅为该格服务**的部分
  （`buildWrongGroupOptions` **不是**——它同时服务错题范围 chips 与举一反三范围解析，
  **必须保留**）。实现时逐个确认引用点，不要整块删。
