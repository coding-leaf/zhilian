# 学习足迹统计设计

## 变更边界

当前页面对课程聚合求和，无法覆盖未分类资料，并且把未登录、失败和未加载都呈现为零。本次只修个人页三项统计的数据来源和加载生命周期，不修改工作台课程聚合、解析流程或题库页面。

## 数据契约

- 新增鉴权只读接口 `GET /materials/statistics`，置于 `/{material_id}` 路由之前。
- 返回必填非负整数 `ready_material_count`、`knowledge_point_count`，不分页。
- 复用 MaterialService / MaterialRepository 既有分层和依赖注入，不引入新服务框架或数据库迁移。
- 两项计数均限制为当前用户、未软删除、`status=ready` 的资料；考点查询同时限制 KnowledgePoint.user_id，避免跨用户串数。
- 计入未分类资料和已归档课程中的资料：学习足迹表达持有的资产；归档不等于删除。页面以简短说明解释资料统计含归档课程。
- 考点按符合条件资料下的知识点实体计数，沿用既有课程统计不筛历史版本的语义。注意现有课程考点聚合没有 ready 条件；本接口依据 PRD R1 加入 ready 条件，不改课程端旧口径。
- 资料数与考点数使用独立聚合或等效标量子查询，避免 join 造成资料数倍增，不逐项查询。
- 已建课程仍为现有 `/folders` 返回的未归档课程列表长度；个人页直接请求该列表取 `items.length`，不依赖其他页面的 folder store 缓存，不从新接口另造一套课程统计。

## 前端流转

在 `src/types/index.ts` 和 `src/api/index.ts` 添加响应类型及普通 GET 调用。`useLearningStatistics` 编排课程列表与资料统计请求；先等 `/folders` 完成（其既有逻辑会清理逾期归档课程），再读资料统计，避免两项跨清理前后取数；不做分页求和。仅在全部加载成功后由 `LearningStatisticsCard` 展示完整三项数字，失败明确显示「加载失败，可下拉重试」和重试按钮，首次加载不先闪零。

`onShow` 重取；`onPullDownRefresh` 重取并在 finally 中停止刷新；开启 `enablePullDownRefresh`。未登录显示登录后查看提示且不请求统计，退出/切换账号后旧请求结果不得恢复旧账号数字。为同一账号的同时刷新合并在途请求或使用请求代次，失败必须可再次发起。

如需提取统计卡片以控制页面体积，仅移动本次统计区块的模板/CSS；个人资料编辑、头像和退出交互保持现有行为。

## 测试与回滚

后端通过真实 SQLite 查询测试空库、仅课程资料、未分类、归档课程、软删除、非 ready、多考点及租户隔离；接口测试认证和静态路由不被动态 ID 捕获。前端组件/页面测试区分成功零值、加载、失败、未登录，并验证两种刷新、重试和账号切换。

最后串行运行 `task verify`，另运行小程序生产构建核对 profile 下拉刷新配置。主会话用本地配置进行只读数据库核对；无环境时如实记录，不能用模拟值冒充实测。无需迁移；回滚本任务代码即可恢复旧行为。
