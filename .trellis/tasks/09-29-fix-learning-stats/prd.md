# 学习数据链路与个人页统计

## Goal

让「我的 → 学习足迹」如实反映用户真实拥有的学习资产，并让**空态与故障态可区分**
（后者是父任务 XAC-4 的落点之一）。

## 现象（2026-09-29 用户实测）

「我的部分，学习足迹为 0」

## 已查明：不是「没有数据」，是**统计口径漏算**

### 前端取值路径

`src/pages/profile/index.vue:25-41` 的三项统计全部来自 `folderStore.folders` 的**课程级聚合字段**：

| 展示项 | 取值 | 行 |
| --- | --- | --- |
| 已建课程 | `folderStore.folders.length` | `:29` |
| 就绪讲义 | `Σ folders[].ready_material_count` | `:113-115` |
| 涵盖考点 | `Σ folders[].knowledge_point_count` | `:117-119` |

### 后端聚合本身是对的

`backend/app/services/folder.py:357-377` 的 `_build_aggregates` 用**批量分组查询**装配计数
（注释明确写着「杜绝逐课程 N+1」），口径本身没有 bug。

### 缺陷在于：**未分类资料不在任何课程分组里，被静默排除**

`folder_id` 为 `NULL` 的资料不属于任何 folder，因而不出现在任何一个 `count_*_by_folder_ids` 的结果中，
前端再对 folders 求和也永远覆盖不到它们。

**实测数据（本次侦察直接查库取得）**：

| 维度 | 实际值 |
| --- | --- |
| 课程文件夹数 | **1** 个（`dec24053…`，未归档，创建于 2026-09-28 08:40 UTC） |
| `ready` 且已归入课程 | 1 份 |
| **`ready` 但 `folder_id IS NULL`（未分类）** | **3 份** |
| `parsing` 未分类 | 3 份 |
| 库中考点总数 | **51** |
| 按课程口径算出的「就绪讲义」 | **1** |

即：用户实际持有 **4 份就绪资料**，个人页最多只会计到 **1 份**；
「涵盖考点」同理只统计那 1 份资料贡献的考点。

### 为什么用户看到的是「全 0」

上述口径缺陷只能解释「少算」，解释不了「全 0」。另有两条会导致**三格全 0** 的路径，
需要在实现前逐条排除（否则会把「多算少算」的问题误当成「全 0」的问题修）：

| 路径 | 锚点 | 判据 |
| --- | --- | --- |
| P1 未登录 | `:121-128` 仅在 `authStore.isLoggedIn()` 时 `loadFolders()` | 未登录 → `folders` 为空 → 三格全 0，且**没有任何文案说明为什么** |
| P2 拉取失败 | `folderStore.loadFolders()` 失败时的处理 | 若失败后 `folders` 保持空数组，视觉上与「真的没有课程」完全一致 |
| P3 数据陈旧 | `pages/profile/index.vue` **没有 `onShow` 刷新**，`pages.json` 也未给该页开 `enablePullDownRefresh` | Tab 页常驻内存，`onMounted` 只跑一次；在别处建了课程/传了资料后回到「我的」，数字可能是旧的 |

P3 是**可真实现**的：`pages.json:23-28` 的 `pages/profile/index` 没有 `enablePullDownRefresh`，
而工作台、学情、讲义详情页都有。个人页是唯一一个**没有任何刷新手段**的 Tab。

## Change Boundary

### In scope

- **R1 统计口径覆盖未分类资料**（前后端各一处，见 Requirements）。
- **R2 空态 / 故障态可区分**：拉取失败必须与「真的没有数据」呈现不同。
- **R3 个人页有刷新手段**：至少 `onShow` 重取 + 补 `enablePullDownRefresh`（与另外两个 Tab 对齐）。
- **R4 复核**：修正后带真实数据核对三项数字与数据库一致。

### Out of scope（明确不做）

- **不改 `_build_aggregates` 的课程级口径本身**：课程内的计数（含 `question_count`、`last_practice_at`）
  是对的，工作台的课程 pill 徽标也依赖它。本次只**新增**「未分类」这一路统计，不动既有分组查询。
- **不做学习时长 / 连续打卡 / 掌握度趋势**等新指标：用户报的是统计数字不对，不是缺少新指标。
- **不改`已建课程`的口径**（`folders.length`，不含已归档）——除非 R4 复核发现它也不对。

## Requirements

### R1 — 未分类资料进统计

- **后端**：为「当前用户的全部资料」提供一组**不按课程分组**的计数口径
  （就绪资料数、考点数），供个人页使用。
  - 实现方向：复用既有 `count_*` 查询的 SQL 条件，去掉 `folder_id IN (...)` 分组约束，
    或在既有 repository 上新增「按用户统计」方法。**优先复用，不新造查询语义**。
  - 必须与既有口径的过滤条件一致：未软删除、`status='ready'`；
    已归档课程的资料是否计入需明确定义并写进 PRD 的 Notes（见下「待决」）。
- **前端**：`readyMaterialCount` / `totalKnowledgePoints` 改为取新的「全量」口径，
  **不再对 folders 求和**；`已建课程` 保持 `folders.length`。
- **契约**：新口径走既有 `/folders` 之外的接口还是扩展既有响应，由 `design`（若判定为复杂）或
  实现时按 `frontend/spec` 的网络层契约决定；**不得在页面里拼装多次请求求和**。

### R2 — 空态与故障态可区分

- `loadFolders` 失败时，个人页必须显示可区分的状态（文案 + 是否有重试入口），
  而不是把 `folders = []` 当成「没有课程」渲染。
- 文案要求：说明是「加载失败，可下拉重试」而不是「暂无数据」。
- 依据：父任务 XAC-4。

### R3 — 刷新手段对齐

- `pages.json` 给 `pages/profile/index` 加 `enablePullDownRefresh`（与工作台/学情一致）。
- 页面补 `onPullDownRefresh` 与 `onShow` 重取统计。

### R4 — 复核

- 用实测账号核对：三项数字分别等于数据库口径算出的值。
- 至少覆盖一个**同时存在「已归入课程」与「未分类」两种资料**的账号状态
  （当前环境恰好就是这种状态：1 份归入 + 3 份未分类）。

## Acceptance Criteria

- [ ] AC-1 未分类的 `ready` 资料被计入「就绪讲义」；其考点被计入「涵盖考点」。
      证据：以当前环境实测（1 归入 + 3 未分类 → 就绪讲义应为 4，而非 1）。
- [ ] AC-2 `已建课程` 仍为 `folders.length`，行为不变（防回归）。
- [ ] AC-3 拉取失败时页面呈现与「真的没有数据」**可区分**（文案不同 + 有重试入口）。
      证据：单测分别断言两条分支。
- [ ] AC-4 个人页支持下拉刷新，且切回该 Tab 时统计会重取。
      证据：`pages.json` 编译产物 + 页面生命周期单测。
- [ ] AC-5 后端新增口径有单测，且覆盖「无未分类资料」「有未分类资料」「资料已软删除」三种情形。
- [ ] AC-6 `task verify` 全绿；`folder` 相关既有用例零回归
      （重点：`backend/tests/unit/services/` 下 folder 聚合用例，以及前端 folder store 用例）。
- [ ] AC-7 三项数字与数据库直查结果一致（复核记录写进 Notes）。

## Notes

- **本任务确实部分依赖 `09-29-fix-parse-stuck`**：那 3 份未分类资料现在是 `parsing`，
  解析修好后它们会变成 `ready`，从而**放大**本缺陷的可见度（从「少算 3 份」变成「少算 3 份且都是用户的全部成果」）。
  但**口径缺陷本身独立存在且已可复现**（当前就有 3 份未分类 `ready`），因此不必等前置任务。
- **待决（实现前须定）**：**已归档课程下的资料是否计入个人页统计？**
  两种口径都有道理——「我的资产」应含归档资料，「当前学习范围」不含。
  倾向：**计入**（个人页表达的是用户拥有的资料总量，归档只是课程维度的整理动作），
  但这会与「已建课程」不含归档产生口径割裂，需在实现时一并定夺并写进 spec。
- **P1/P2/P3 三条路径尚未排除**。实现 R1 之前必须先判定用户看到的「全 0」是哪一条
  （或哪几条叠加），否则「少算」修好了、「全 0」依旧。判定手段：以实测账号登录后直查
  `/folders` 与用户资料计数的接口响应，与页面渲染值逐项比对。
- 个人页当前是**唯一没有任何刷新手段**的 Tab，这本身就是一条独立可用性缺陷，
  与统计数字对不对是两件事——R3 单独覆盖它。
