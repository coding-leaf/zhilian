# 学情页信息架构复核

## Goal

对「学情」页当前的信息架构给出一个**有依据的判定**：维持现状、只修空态、还是重设计。
本任务**不预设结论**——它是一个复核任务，不是重设计任务。

## 为什么单列且加门禁

用户原话：「学情界面，意义不明？感觉可能要重新设计，**不排除因为前面链路阻断导致我无法使用**」。

这句话里有一个问号和一个自己给出的反例，说明**用户本人也不确定这是不是设计问题**。
在链路修复前判定「需要重设计」，等于照着残缺信息做设计。

**门禁：本任务在 `09-29-fix-learning-stats` 完成前不启动。**
届时应已具备：解析就绪的资料、生成过的题目、至少一次完整作答与其诊断报告、
以及个人页统计已恢复真实的资产数字。

## 现状（当前实现的客观描述）

`src/pages/review/index.vue` 共四段：

| 区块 | 内容 | 数据源 |
| --- | --- | --- |
| 学情全景（summary 卡） | 待攻克错题 / 已消灭错题 / **归属范围** | `wrongRecords` 计算 + `groupOptions.length` |
| 我的练习 | `PracticeEntryCard` 列表（可续答/看报告） | `practiceStore.loadPractices` |
| 错题巩固 | 范围 chips + 「举一反三」批量再生题入口 | `buildWrongGroupOptions` |
| 错题列表 | `WrongRecordCard` 列表 | `apiListWrongRecords` |

零数据下的实际呈现：三个数字全为 0、0、0；三个区块各自的空态文案
（「太棒了！当前范围内没有待巩固的错题。」等）叠在一起，整页没有任何「我该先做什么」。

## 待复核的核心问题

1. **「归属范围」这一格表达什么？** 当前是 `groupOptions.length`（错题涉及多少个课程/资料范围）。
   对用户而言，「归属范围 = 0」既可能是「没有错题」，也可能是「错题还没归属课程」——
   两种完全不同的处境共用一个数字。
2. **零数据下整页有没有引导？** 当前没有。用户看到的是「太棒了！没有错题」这样的**伪正向**文案——
   而事实是他**还没做成过任何一次练习**。「没有错题」与「还没开始」在体验上必须分开。
3. **信息架构的边界是否清楚？** 学情（诊断与错题）与工作台（资料与出题）的职责划分，
   在「我的练习」这一段上是重叠的——工作台与学情都能进入练习。
4. **入口顺序是否合理？** 页面把「我的练习」放在错题之前，但标题主打「学情全景与错题巩固」——
   零练习时第一屏是一张全 0 的卡。带真实数据后这个顺序是否还成立，需要重新看。

## Change Boundary

### In scope

- **R1 带真实数据复核**：在门禁解除后的真实账号状态下走一遍该页，逐段记录
  「用户此刻能不能看懂这一屏在说什么、下一步该做什么」。
- **R2 给出判定**：三选一并写明依据（对应 R3/R4/R5）。
- **R3 若判定为「空态表达问题」**：只修空态与文案，不改结构。
  重点修掉「伪正向」文案（把「没有错题」与「还没做过练习」分开）。
- **R4 若判定为「信息架构问题」**：产出重设计方案（信息分层、区块顺序、职责边界），
  **作为独立任务立项**，不在本任务内实现。
- **R5 若判定为「维持现状」**：写明理由并关闭本任务，把结论留档。

### Out of scope

- **不在本任务内实现任何重设计**（见 R4：结论若为重设计，另立任务）。
- **不动 `09-29-fix-learning-stats` 的个人页统计**——两页是不同 Tab、不同职责。
- **不引入新的学习指标**（掌握度趋势、学习时长等）：那是产品新增，不是本页复核。

## Requirements

### R1 — 复核必须基于真实数据

- 禁止在零数据状态下做判定（这正是门禁存在的原因）。
- 复核记录必须包含：当时的练习数、错题数、错题归属分布、个人页三项统计值。
- 依据父任务 XAC-4：若复核中发现任何「空态与故障态不可区分」的地方，**登记为缺陷**，
  不管它属于本页还是别的页。

### R2 — 判定必须可反驳

- 结论不能是「感觉不太行」，而要指出**具体哪一屏、哪个数字、哪种用户处境**下不成立，
  以及**改什么**能让它成立。

## Acceptance Criteria

- [ ] AC-1 复核在门禁解除后、**非零数据**状态下完成，记录真实数据快照。
- [ ] AC-2 产出明确判定（维持 / 修空态 / 重设计）并写明依据与具体的屏/数字/处境。
- [ ] AC-3 若判定为「修空态」：文案与空态改动落地，且「没有错题」与「还没做过练习」可区分。
- [ ] AC-4 若判定为「重设计」：重设计方案作为独立任务的 PRD 落地，**本任务不含实现**。
- [ ] AC-5 「归属范围」这一格给出明确处置（保留并改标签 / 换指标 / 删除），不留悬空。
- [ ] AC-6 若本任务含代码改动，`task verify-frontend` 全绿且学情页既有用例零回归。

## Notes

- **本任务的价值可能主要是「不做」**：如果链路修好后这一页就说得通了，
  那么正确结论就是维持现状。把「看起来乱」当成「设计烂」是本次最容易犯的错。
- 用户用了「意义不明？」——这更像**缺一个说明这页是干什么的入口说明**，
  而不是结构错误。零数据下三个 0 加三句「太棒了」，确实无法自解释。这个可能性要在复核时优先验证。
- 学情页有 `enablePullDownRefresh`（`pages.json:16-22`），刷新手段比个人页完整——
  这条差异在复核个人页时可作对照。
