# PRD: 资料生命周期闭环、资料列表展示与持久化、用户鉴权恢复

## 1. 背景与现状 (Context)
用户在实机使用智练平台时，遭遇了三大阻断性端到端体验问题：
1. **上传资料后解析体感过慢**：虽然后台采用了异步队列处理，但前端上传成功后，用户留在首页或列表页时没有清晰的阶段感知与自适应轮询反馈，导致用户认为“假死”或“卡死”。
2. **点击全部资料显示为空，返回后资料全部丢失**：
   - 首页 `RecentLearningSection` 底部提供“查看全部资料”入口，跳转至 `/subpackages/material/pages/list/index`；
   - 列表页目前仅在 `onMounted` 时调用了一次 `loadData(true)`，如果页面被二级缓存或在页面返回时，`onShow` 未进行保活刷新；
   - 列表页与首页共享 `useMaterialStore` 的 `materialsList`：列表页加载全部资料（覆盖为 20 条）或重置时，用户回退至首页，首页未在 `onShow` 刷新首页切片（首页需要 5 条或全局展示），造成首页展示与列表页互相干扰，甚至在未登录或异常时状态被空数组覆盖清空，且没有独立列表状态分离；
   - 列表页在筛选 Tab 切换和分页时存在状态竞态，且缺少明确的解析中徽标动态刷新。
3. **怀疑用户登录授权不稳定 (User Auth State)**：
   - 小程序冷启动通过 `App.vue` 中的 `onLaunch` 恢复本地 Token，但热启动或切后台重新激活时缺乏 Token 有效性检查与静默校验证明；
   - 用户画像 `profile`（包括 `id`, `nickname` 等）未持久化到本地存储（受 3-key 白名单影响），导致冷启动后虽然有 `auth_tokens`，但 `userStore.profile` 为 `null`，首页将用户显示为“认证学员”或“未登录”，使人误以为未登录；
   - 缺少启动时调用 `fetchUserProfile()` 自动补全用户信息闭环。

---

## 2. 目标与非目标 (Goals & Non-goals)

### 2.1 目标 (Goals)
1. **列表页与全局状态解耦与保活**：
   - 列表页进入和切回（`onShow`）时必须具备自动保证数据新鲜度的机制；
   - 首页与列表页各取所需：列表页独立管理分页列表数据，不再粗暴覆写首页的精简概览数据，避免回退首页后资料显示错乱或丢失；
   - 列表页 Tab 切换（全部/解析中/待重拍/已完成）准确过滤对应状态（`parsing` 映射 `pending,parsing`，`ready` 映射 `ready,completed`）。
2. **解析慢与弱网体感提速**：
   - 上传成功后立即在本地 Pinia 及列表呈现为 `parsing` / `pending` 状态的瞬时占位卡片；
   - 列表页对处于 `parsing`/`pending` 状态的资料自动拉起退避轮询调度，解析完成（变为 `ready`）后就地无感刷新，无需用户手动下拉；
   - 支持清晰的“正在深度解析中，正在提取考点大纲...”进度阶段提示文案。
3. **登录鉴权长效稳定与画像自愈**：
   - 在 `userStore` 中提供健全的鉴权水合机制（Hydration）：冷启动从 `auth_tokens` 恢复后，若已鉴权则静默拉取 `fetchUserProfile()` 填充 `profile`；
   - 修复登录页与工作台的认证状态响应式联动，消除“明明登录了却提示未登录或空白”的假象。

### 2.2 非目标 (Non-goals)
- 不修改数据库物理表结构与既有 OpenAPI 契约；
- 不改写 OCR/LLM 核心算法流程（本任务聚焦上层用户可感知链路闭环）。

## 3. 用户故事与验收标准 (Acceptance Criteria)

### AC 1: 资料列表完整展示与跨页面导航持久
- [ ] 用户在首页点击“查看全部资料”进入列表页，列表页在 `onShow` 自动拉取第一页最新资料，完整渲染已上传的全部资料卡片。
- [ ] 用户从列表页返回首页，首页的“最近学习”与“掌握度”卡片保持正常展示，绝不出现“数据被冲掉/全部丢失”的现象。
- [ ] 切换列表页顶部 Tab（全部 / 解析中 / 待重拍 / 已完成），能正确按状态筛选资料，当列表为空时展示友好的空状态卡片。

### AC 2: 资料解析体感与就地感知闭环
- [ ] 上传模态弹窗点击上传成功后，首页与列表页能立即感知到新增的资料条目，并显示“解析中”标签。
- [ ] 列表页如果存在未完成资料，启动自适应长轮询追踪状态变迁，完成后自动转换为“已完成”并展示提取到的考点数量。

### AC 3: 用户鉴权稳定性与画像恢复
- [ ] 用户登录成功后，Token 存入本地白名单，用户信息与登录态在小程序重新打开后依然保持有效。
- [ ] 每次应用启动及切前台若持有 Token，静默水合 `fetchUserProfile` 获取最新用户昵称与 ID，避免回退为未登录假态。
- [ ] 若 Token 真正过期或失效，请求拦截器平滑引导去重新登录，不触发死循环。
