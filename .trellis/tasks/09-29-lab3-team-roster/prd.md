# 小组分工与个人工作小结（含防泄露闸门）

> 父任务：`09-29-lab3-delivery-wrapup`，覆盖其 **R3**。
> **排期约束**：AC-4 的闸门必须在**任何提交发生之前**就位，故本任务的闸门部分
> 应最先执行，早于其它子任务的提交动作。

## Goal

满足老师第 3 条：讲清小组分工与完成情况，并给出**每位成员的个人工作小结**。
由于仓库公开，实现方式是**物理分离**：真名版落在仓库外，仓库内只放代号版。

## 需求

- R3.1 仓库外 `D:\code\Workspace\zhilian-lab3-deliverables\` 写真名版：
  四人角色、职责边界、RACI 矩阵、代码所有权，以及**每人一节个人工作小结**。
- R3.2 仓库内 `docs/团队分工.md` 写代号版，沿用《代码管理工作介绍》既有别名
  （TechLead / SecLead / Reviewer / DevOpsLead），附别名↔角色对应表。
- R3.3 提交前拦截闸门，见 AC-4。

## 个人小结的写法（关键约束）

**按仓库真实产物回填**，不写空话。每人一节需能对上：拥有的目录（对齐父任务
`docs/团队分工.md` 的所有权表）、经手的 ZL 任务编号、代表性提交、验证证据。
目的是让老师拿提交记录核对时对得上，而不是读到一段无法验证的自述。

  同一改动可通过；随后恢复钩子并清理测试提交
- [ ] AC-5 闸门命中时不回显姓名本身（只给文件名与行号）
- [ ] AC-6 处置「`miniprogram/` 所有权在两份文档间冲突」：**以《代码管理工作介绍》为准**
