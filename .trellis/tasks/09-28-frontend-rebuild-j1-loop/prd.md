# 前端完全重构与J1端到端切片闭环 (PRD)

## 1. 目标与用户价值 (Goal & User Value)
彻底推倒原残缺混乱的 `miniprogram` 前端，采用现代化的 Uni-app (Vue 3 + TS + Vite) + UnoCSS + 现代化组件库（Wot Design Uni）重新初始化工程底座。
视觉风格采用“温润学术 / 纸质阅读风”（米白暖色底、墨黑文本、克制学术色系）。
优先单兵突击打通 **J1 首次完整学习闭环**：用户导入一份讲义资料 -> 解析完成并智能出题 -> 预览确认题目 -> 进入专注练习作答 -> 答题交卷并触发诊断 -> 自动生成并可直达查看深度诊断报告与薄弱点。杜绝半成品跳页与空页面，提供可观测、可自愈的端到端学习体验。

## 2. 需求清单 (Requirements)

### R1. 工程底座彻底重构与设计规范 (Design System & Foundation)
- **R1.1 脚手架与依赖**：清空旧前端，重构为 Uni-app (Vue 3 + TS + Vite) 规范工程，引入 UnoCSS 驱动 Design Tokens，接入 Wot Design Uni 组件库。
- **R1.2 温润学术设计语言**：建立统一的主题色盘（纸张底色 `#F8F6F0` / `#FAF9F6`，正文墨色 `#1C1917`，辅助次灰 `#57534E`，学术青 `#0D9488` / 书卷蓝 `#1E3A8A`，强调橘 `#D97706`），卡片质感温润柔和。
- **R1.3 核心路由与分包收敛**：
  - 主包 3 Tab：工作台 (`pages/index/index`)、学情与错题 (`pages/review/index`)、我的与设置 (`pages/profile/index`)。
  - 核心业务分包：
    - `subpackages/material`：导入质检、课程/资料详情、知识树出题配置、题目预览与核对；
    - `subpackages/practice`：练习专注会话、草稿保存、交卷过渡；
    - `subpackages/report`：学情诊断报告详情、题目深度解析、错题本。
  - 清理所有重复登录页与无用占位页（如原无意义的 `report/index`）。

### R2. 强类型 API 客户端与网络层 (Robust API Client)
- **R2.1 强类型契约**：严格根据后端已实现的 RESTful 接口（`/api/v1/auth/*`, `/api/v1/materials/*`, `/api/v1/questions/*`, `/api/v1/practices/*`, `/api/v1/folders/*`）编写强类型请求与响应接口。
- **R2.2 自动认证与异常自愈**：统一封装 `request`，支持微信登录 Token 注入、401 无感刷新/拦截、网络超时重试与用户友好的错误 Toast。

### R3. J1 核心学习闭环垂直切片 (J1 Vertical Slice)
- **R3.1 资料导入与解析流转**：
  - 支持微信聊天文件 (`wx.chooseMessageFile`) 与图片/拍照导入。
  - 导入后轮询或监听资料状态（`WAITING` -> `PROCESSING` -> `PARSED` / `FAILED`），支持解析失败重试。
- **R3.2 智能出题与题目核对**：
  - 从资料或课程发起出题，设置题数与难度。
  - 出题完成后展示题目列表，包含题型标签、来源讲义锚点、参考答案与解析。
  - 提供醒目的“开始答题”行动点（Action Bar）。
- **R3.3 练习作答与状态机持久化**：
  - 单题/卡片沉浸式作答，支持单选、多选、判断、简答题（主观题）。
  - 作答状态实时本地持久化（答题草稿 `saveAnswerDraft`），防意外切后台或误关导致答案丢失。
  - 答题卡进度概览，提交前提示未作答题数。
- **R3.4 交卷流转与真实诊断生成**：
  - 点击交卷调用 `POST /api/v1/practices/{id}/submit`。
  - 触发或轮询诊断生成 `POST|GET /api/v1/practices/{id}/diagnosis`。
  - 诊断生成后无缝跳转至真正的报告页 `subpackages/report/pages/detail/index`，杜绝跳转至占位页。
- **R3.5 真实学情诊断报告展示**：
  - 展示综合得分、雷达图/掌握度分级、薄弱知识点清单。
  - 逐题判题依据展示（得分点、命中/遗漏要点、讲义原文片段）。
  - 提供明确的“继续练习薄弱点”或“返回工作台”下一步闭环入口。

## 3. 验收标准 (Acceptance Criteria)

- [x] **AC-1 (工程与规范)**：`pnpm run lint`、`pnpm run type-check` 与 `pnpm run test:unit` 全部通过，无 TS 报错与无用 eslint 告警。
- [x] **AC-2 (视觉一致性)**：整体 UI 统一呈现温润学术/纸质阅读风格，背景、排版、卡片及组件风格统一。
- [x] **AC-3 (J1 黄金链路端到端可用)**：
  - 测试账号从工作台上传一份资料（PDF/图片）；
  - 资料成功解析后，配置并生成 3~5 道题；
  - 在题目列表核对后点击“开始答题”，正常进入作答界面；
  - 完成作答并交卷，平滑过渡并成功生成诊断报告；
  - 自动打开诊断报告页面，能清晰查阅题目得分、判题要点、讲义出处及薄弱点；
  - 全流程无白屏、无报错、无重定向死循环、无断头跳转。
- [x] **AC-4 (容错与中断恢复)**：作答过程中退出小程序再重新进入，草稿答案依然保留，能够无缝继续作答。

## 4. 边界与范围 (Out of Scope)
- J2 复杂的单页多图重拍与 OCR 质检报告展示（本切片先支持基础图片导入解析）。
- J7 高级错题本多维时间筛选与离线自评历史对比。
- J8 用户账号注销与数据导出等边缘合规页面。
