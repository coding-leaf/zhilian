## 1 依赖漏洞扫描（pip-audit）

### 1.1 首次扫描（修复前）

```bash
$ uv run pip-audit --desc
Found 1 known vulnerability in 1 package
```

| 项 | 值 |
| --- | --- |
| 包 | `pyjwt` 2.14.0 |
| 漏洞 ID | `PYSEC-2026-4141` |
| CWE | CWE-248（未捕获异常） |
| 修复版本 | `2.15.0`（维护者已发布） |
| 描述 | `PyJWKClient.get_signing_key_from_jwt(token)` 在解码未验证 token 时可能抛未捕获异常；**非认证绕过、非进程崩溃**（维护者确认）；受影响范围 `>= 2.0.0a1, <= 2.14.0` |

### 1.2 影响评估（项目视角）

| 评估维度 | 结论 |
| --- | --- |
| 项目是否使用受影响 API | **否**。项目仅用 `jwt.encode()` / `jwt.decode()`（HS256 对称签名），未使用 `PyJWKClient`（见 `app/core/security.py`） |
| 实际可利用性 | **极低**（不可达代码路径） |
| 等级判定 | **中危**（非高危），但准出以「零漏洞」为更严标准 |

### 1.3 修复动作

```bash
$ uv lock --upgrade-package pyjwt
Updated pyjwt v2.14.0 -> v2.15.1
```

| 项 | 值 |
| --- | --- |
| 修复方式 | 锁文件升级 `uv.lock`（`pyproject.toml` 约束 `pyjwt>=2.8.0` 无需变更） |
| 升级结果 | `pyjwt 2.14.0` → **`2.15.1`**（超出最低修复版本 2.15.0） |
| 兼容性 | 小版本升级；`jwt.encode`/`jwt.decode` 接口无破坏性变更 |

## 2 代码安全静态扫描（bandit）

### 2.1 扫描结果汇总

```bash
$ uv run bandit -r app -f json -q
严重级别统计: {'LOW': 3, 'MEDIUM': 2}
置信度统计: {'HIGH': 5}
总数: 5
```

| 严重级别 | 数量 | 是否阻塞 |
| --- | ---: | :---: |
| **HIGH** | **0** | — |
| MEDIUM | 2 | ❌ 不阻塞（已评估） |
| LOW | 3 | ❌ 不阻塞 |

### 2.2 逐项评估

| # | 规则 | 位置 | 级别 | 评估与处置 |
| ---: | --- | --- | :---: | --- |
| 1 | B314 XML 解析 | `app/services/material.py:226` | MEDIUM | **已评估**：代码已有 `# noqa: S314` 注释，说明为标准库解析**可控 OOXML**（用户上传资料，非任意外部 XML）。**风险接受**。 |
| 2 | B314 XML 解析 | `app/services/material.py:297` | MEDIUM | 同上（PPTX 解析路径）。**风险接受**。 |
| 3 | B406 import_xml | `app/cli/fixtures.py:14` | LOW | CLI 测试夹具导入 XML 模块，非生产请求路径。**风险接受**。 |
| 4 | B311 random | `app/integrations/embedding/fake.py:82` | LOW | **fake 适配器**（测试替身）使用 `random` 生成模拟向量，非安全上下文。**风险接受**。 |
| 5 | B405 import_xml | `app/services/material.py:18` | LOW | `ElementTree` 导入（配合已评估的 B314）。**风险接受**。 |

### 2.3 结论

> **bandit 无 HIGH 阻塞项**。2 个 MEDIUM（XML 解析）与 3 个 LOW 均已逐项评估并给出「风险接受」依据，非阻塞项登记见《技术债清单》TD-07。
