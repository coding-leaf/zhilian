# 评审检查清单（中期质量检查 · 正式代码评审）

> **评审原则**：对事不对人；控制时长；以本检查清单为准；避免风格争论。
> **评审形式**：作者讲解 → 评审人提问 → 记录问题 → 分级 → 给出结论。

---

## 8 项评审检查清单

| # | 维度 | 关键问题 |
| ---: | --- | --- |
| 1 | **正确性** | 逻辑是否符合需求？测试断言是否反映真实业务行为？是否漏掉边界条件？ |
| 2 | **设计** | 职责是否单一？耦合是否合理？fixture 复用是否到位？测试结构是否清晰？ |
| 3 | **可读性** | 命名是否符合规范？结构是否清晰？注释是否准确？是否有冗余信息？ |
| 4 | **健壮性** | 异常处理是否完整？边界是否覆盖？错误码是否一致？日志是否得当？ |
| 5 | **安全与性能** | 是否有注入风险？权限边界是否守住？SQL 是否合理？是否有并发缺陷？ |
| 6 | **测试充分性** | 关键分支是否覆盖？等价类 / 边界值 / 错误推测 / 路径覆盖是否到位？ |
| 7 | **可维护性** | 是否易于扩展？是否易于调试？断言失败时定位是否清晰？ |
| 8 | **文档与追溯** | 是否关联 P 编号 / 缺陷编号？后续维护者能否理解「为什么这样写」？ |

---

## 问题分级标准

| 级别 | 含义 | 处理 |
| :---: | --- | --- |
| **🔴 阻塞** | 必须修复后才能合并 | PR 必须修改后再次评审 |
| **🟠 重要** | 应该修复但不阻塞 | 作者可在后续 PR 修复，但需登记在案 |
| **🟡 建议** | 可改进项 | 评审人建议，作者可自由决定 |

---

## 评审结论模板

每个 PR 必须给出以下三种结论之一：

| 结论 | 含义 | 下一步 |
| --- | --- | --- |
| ✅ **通过** | 无阻塞 / 无重要问题 | 合并 |
| 🟡 **修改后通过** | 有重要问题但可在同一 PR 内修复 | 作者修改后评审人复核 → 合并 |
| ❌ **不通过** | 有阻塞问题 | PR 必须重写或拆分 |

---

## 时间预算

每个 PR 评审时长：15-25 分钟（含作者讲解 5 分钟 + 评审人提问 5-10 分钟 + 讨论与分级 5-10 分钟）

| ---: | --- | ---: |
| PR1 | P1-4 folder_id 回归保护 | 20 min |
| PR2 | 错误契约补测 | 25 min |
| PR3 | deps/user.py 覆盖率提升 | 20 min |
| PR4 | practice 状态机与幂等 | 20 min |
| **合计** | — | **85 min** |
