## 3 影响分析

### 3.1 C-1 `app/core/errors.py`

| 影响维度 | 分析 |
| --- | --- |
| 影响范围 | 3 个错误类的 `details` 字典结构 |
| 上游调用方 | 所有实例化这 3 个错误类的服务/路由（间接） |
| 行为变化 | `attempt_item_id` 等参数注入**现在正确保留**（此前被 `detail` 别名覆盖） |
| 兼容性 | **向后兼容**：`details` 字典变为超集（修复前为子集），读取方不受影响 |
| 风险等级 | **高**（错误契约是 API 响应面）→ 触发评审会全量评审 |
| 回归策略 | T-1 全量契约测试 + 全量 1528 回归 |

### 3.2 C-2 `app/services/practice.py`

| 影响维度 | 分析 |
| --- | --- |
| 影响范围 | `retry_grading` 的事务边界与异常类型 |
| 上游调用方 | `app/api/routers/practice.py`（重试判题接口） |
| 行为变化 | ① 二次校验失败时正确回滚（此前状态永久卡 SUBMITTED）；② 非 `(QueueError, SQLAlchemyError)` 异常不再被吞掉 |
| 兼容性 | **向后兼容**：正常路径行为不变；异常路径包装为 `PracticeStatusError` 仍抛出 |
| 风险等级 | **高**（状态机 + 事务边界）→ 触发评审会全量评审 |
| 回归策略 | T-4 状态机 6 状态参数化 + 入队失败回滚 + 全量回归 |

### 3.3 C-3 `uv.lock`（pyjwt 升级）

| 影响维度 | 分析 |
| --- | --- |
| 影响范围 | JWT 签发/校验（auth 全链路） |
| 行为变化 | `jwt.encode` / `jwt.decode` 接口无破坏性变更 |
| 兼容性 | **向后兼容**（小版本升级） |
| 风险等级 | **中**（安全依赖） |
| 回归策略 | auth/security 专项测试 + 全量 1528 回归 + pip-audit 复扫 |

### 3.4 测试代码变更（T-1 ~ T-5）

| 影响维度 | 分析 |
| --- | --- |
| 影响范围 | 仅测试套件，不影响运行时 |
