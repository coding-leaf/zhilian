# 缺陷记录表模板

> 用途：中期质量检查期间所有缺陷、评审打回项、门禁异常的统一台账。
> 收口要求：里程碑收口时**无 open 项**——要么已修，要么写成显式决策（理由 + 影响 + 下一步）。
> 编号规则：项目既有缺陷沿用 `docs/后续待解决问题.md` 的编号（P0-x / P1-x / P2-x / E-x / D-x），
> **不另造**；本次新发现的用 `Q-xx` 顺延编号。

---

## 台账纪律

| 规则 | 说明 |
| --- | --- |
| 失败先记录再处理 | 门禁/测试失败先建条目，不跳过 |
| 抖动要记账 | E-1 类墙钟抖动不计阻断，但**必须**进台账 |
| 评审打回进台账 | 评审打回项与代码缺陷同表，统一跟踪 |
| 收口清空 | 里程碑收口时台账无 `open`；`deferred` 必须有决策段 |
| 不写空话 | "后续优化""待改进"不是下一步；要写可验收的动作 |
