[  6219,   753] 4.1测试目的
[  6398,   997] 计算机软件的测试目的是：
[  6586,   987] a）验证软件是否满足软件开发合同或项目开发计划、系统/子系统设计文档、软件需求规格说明、
[  6770,  1230] 软件设计说明和软件产品说明等规定的软件质量要求：
[  6944,   987] b）
[  6953,  1230] 通过测试，发现软件缺陷；
[  7127,   982] c）为软件产品的质量测量和评价提供依据。
[  7311,   753] 4.2测试类别
[  7500,  1001] 根据GB/T8566的要求.本标准对如下测试类别作详细描述：
[  7673,   982] a）单元测试；
[  7843,   973] b）集成测试：
[  8046,   987] c）
[  8046,  1216] 配置项测试（也称软件合格性测试或确认测试）；
[  8210,   973] d）系统测试；
[  8403,   987] e）验收测试。
[  8592,  1006] 可根据软件的规模、类型、完整性级别选择执行测试类别，
[  8775,  1011] 回归测试可出现在上述每个测试类别中，并贯穿于整个软件生存周期，故单独分类进行描述。

[  1125,   586] 4.3测试过程
[  1309,   591] 4.3.1概述
[  1488,   841] 软件测试过程一般包括四项活动·按顺序分别是：测试策划、测试设计、测试执行、测试总结。
[  1672,   591] 4.3.2测试策划
[  2036,   601] 提出测试的基本方法；确定测试的资源和技术需求；进行风险分析与评估：制定测试计划（含资源计划和
[  2220,   596] 进度计划）。有关测试计划的内容和要求见GB/T9386。
[  2399,   596] 4.3.3测试设计
[  2584,   841] 依据测试需求·分析并选用已有的测试用例或设计新的测试用例：获取并验证测试数据：根据测试
[  2957,   606] 行测试就绪评审，主要评审测试计划的合理性和测试用例的正确性、有效性和覆盖充分性，评审测试组
[  3131,   601] 织、环境和设备工具是否齐备并符合要求。在进人下一阶段工作之前·应通过测试就绪评审。
[  3301,   586] 4.3.4测试执行
[  3490,   827] 执行测试用例·获取测试结果；分析并判定测试结果。同时，根据不同的判定结果采取相应的措施；
[  3863,   596] 定是停止测试，还是需要修改或补充测试用例集，并进一步测试。
[  4043,   591] 4.3.5测试总结
[  4227,   836] 整理和分析测试数据：评价测试效果和被测软件项·描述测试状态。如，实际测试与测试计划和测
[  4406,   601] 试说明的差异、测试充分性分析、未能解决的测试事件等：描述被测软件项的状态，如，被测软件与需求
[  4590,   596] 的差异，发现的软件差错等：最后，完成软件测试报告，并通过测试评审。
[  4770,   591] 4.4测试方法
[  4954,   586] 4.4.1静态测试方法
[  5138,   836] 静态测试方法包括检查单和静态分析方法-对文档的静态测试方法主要以检查单的形式进行，而对
[  5313,   591] 代码的静态测试方法一般采用代码审查、代码走查和静态分析，静态分析一般包括控制流分析、数据流
[  5502,   596] 分析、接口分析和表达式分析。
[  5681,   841] 应对软件代码进行审查、走查或静态分析：对于规模较小、安全性要求很高的代码也可进行形式化
[  5860,   591] 证明。
[  6045,   586] 4.4.2动态测试方法
