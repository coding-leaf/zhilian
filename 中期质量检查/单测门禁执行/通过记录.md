## 3 合并门禁语义（关键约定）

### 3.1 机器门禁（自动化）

> **PR → master 的合并必须有 4 道机器门禁全部 green，否则 GitHub 拒绝合并按钮。**

```
PR opened
   ↓
┌─────────────────────────────────────────────┐
│  Backend job (verify.yml)                   │
│  ├── ruff format --check .                 │ ✓
│  ├── ruff check .                          │ ✓
│  ├── mypy app                              │ ✓
│  ├── lint-imports                          │ ✓
│  ├── pytest (cov ≥80% + xml)              │ ✓  1496 passed
│  ├── diff-cover (增量 ≥80%)                │ ✓
│  ├── T0 核心覆盖率 ≥90%                    │ ✓  99%
│  └── T0 deps 覆盖率 ≥80%                   │ ✓  84%
└─────────────────────────────────────────────┘
   ↓
┌─────────────────────────────────────────────┐
│  Frontend job (verify.yml)                 │
│  ├── eslint                                │
│  ├── vue-tsc 类型检查                       │
│  └── vitest --coverage                     │
└─────────────────────────────────────────────┘
   ↓
┌─────────────────────────────────────────────┐
│  SonarCloud job (verify.yml)               │
│  └── 静态扫描（SONAR_TOKEN 未配时短路）       │
└─────────────────────────────────────────────┘
   ↓
PR mergeable
```

### 3.2 配置位置

| 项 | 位置 |
| --- | --- |
| **本地门禁** | `Taskfile.yml::verify-backend`（14 行命令） |
| **CI 门禁** | `.github/workflows/verify.yml::backend`（34-89 行 step） |
| **分支保护规则** | GitHub `Settings → Branches → Branch protection rules → master` |
| **必填检查项** | `verify` workflow（backend/frontend/sonar 三个 job 同时 green） |

### 3.3 本地与 CI 的不变量

> **本地跑绿即 CI 跑绿**。CI 命令**精确镜像** `Taskfile.yml`，**不另立第二套门禁**。

| 门禁 | 本地 | CI |
| --- | --- | --- |
| 后端 | `task verify-backend` | 同一串命令 |
| 前端 | `task verify-frontend` | 同一串命令 |
| 全部 | `task verify` | 两个 job 并行 |

### 3.4 分支保护规则配置（手工一次性）

> 详见 `中期质量检查/环境与CI准备.md` §2.3。

GitHub → 仓库 `Settings` → `Branches` → `Branch protection rules` → `master`：

1. ✅ **Require status checks to pass before merging** —— 把 `verify` 加入必需检查
2. ✅ **Do not allow bypassing the above settings**
3. ✅ **Require approvals**（1 人）+ **Require review from Code Owners**
4. ✅ **Require conversation resolution before merging**

> **代码评审与单测门禁的关系**（不变）：
> 机器管「人容易漏的」——静态检查、类型检查、架构契约、单测、覆盖率门槛、静态扫描；
> 人管「机器看不见的」——接线是否正确、归因是否成立。
> **两者互补，而不是用一个假装成另一个。**
